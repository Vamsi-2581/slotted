## Necessity

The asterisk is the convention. A form where most fields are required marks the exception instead: `optional` writes _(optional)_ on the fields a reader may skip, and `words` writes both. The glyph is hidden from assistive technology because `aria-required` on the control already says it once.

## Label placement

A side label sits beside its control and stacks below 320 pixels of the field's own width, so the same field reflows inside a drawer and stays aligned in a page grid. The field is its own container; the window width plays no part.

## Sizes

Three steps that match the control the field wraps. Every step reads the control type scale, so the label, the message and the counter follow the density the application sets.

<Example name="sizes" />

## States

`invalid` sets `aria-invalid` on the control and joins the error to its description. `disabled` and `readOnly` are the native attributes; `required` is `aria-required`.

<Example name="states" />

## Messages

A description and an error share one slot below the control. `reserve` holds the line open so the layout does not move when an error appears, and a warning that does not block submission is the same part in another tone.

<Example name="messages" />

## Counter

The page owns the number and the field owns where it sits: the counter joins the label row and the control's description.
