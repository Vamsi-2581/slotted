# `code-block` — capability inventory

Wave 8, round 11. Read on 2026-09-14, before any of this family's code was
written. `docs/component-features.md` §10 gives the family two lines —
language, highlighting, optional line numbers, wrap, copy, a filename,
highlighted lines; the code stays copyable text; contrast and the scroll's
focus are right; **the highlight engine is an optional package** — and
`docs/process/build-order.md` records three families that deferred to it by name:
`prose` (highlighting, a copy control, line numbers and a wrap toggle "belong
to `code-block` in wave 8"), `description-list` (the copy control's glyph and
the `copyable` capability, "and `code-block` in wave 7 needs the same mark"),
and `scroll-area` (`prose`, `table` and `tabs` each wrote their own scroll
measure before it existed, "and each one takes the family when it is opened
next" — this family is opened after it, and takes it from the start).

`docs/product/prd.md` §40 is the question this family turns on: prefer a dependency
when the problem has significant complexity and an established implementation
exists; prefer the platform when it already gives most of the answer. Both
apply, to two different halves. Tokenising a language is the first — a
grammar per language is what Shiki and Prism are, and none of it is written
here. Drawing a block of lines is the second — `<pre><code>` is the platform's,
and the family adds the parts a documentation page and a developer console
need around it.

## 1. Surveyed

Eight sources, read 2026-09-14. They split on **who tokenises**:

- **Engines** — Shiki, Prism — produce tokens or HTML from a grammar and draw
  nothing.
- **Frames** — Carbon, Docusaurus, Mantine, Expressive Code — draw the box,
  the gutter, the copy control and the markers, and each one takes an engine
  underneath: Prism in Docusaurus, Shiki in Expressive Code and Mantine (or
  highlight.js), none in Carbon.

Two specifications were read for the wiring and none for the block as a whole,
because the APG index holds no code pattern:

- WCAG 2.2 [SC 2.1.1 Keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)
  and the [`scrollable-region-focusable`](https://accessibilityinsights.io/info-examples/web/scrollable-region-focusable/)
  rule it is tested by, which `scroll-area`'s contract already records: a
  block wider than its box has to be scrollable by keyboard, and the tab stop
  that makes it so owes a name.
- WCAG 2.2 [SC 1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html):
  content at 320 pixels without two-dimensional scrolling, except where
  two-dimensional layout is part of the meaning. Code is the named exception
  and the wrap toggle is the answer to it anyway — a reader who cannot scroll
  sideways can wrap.

Inside this repository, five families were read for the boundary and not for
the survey:

- `prose` draws a fence — the ground, the edge, the inset, `direction: ltr`,
  the mono face at `0.9em` — and defers everything else here. This family's
  fence agrees with `prose`'s in every measure, so a Markdown page that
  upgrades a fence to `code-block` moves nothing.
- `description-list` holds `copyable`: `@slotted/core/clipboard`'s
  `writeToClipboard`, `data-complete` on the control for two seconds, the check
  glyph in place of the two sheets, the outcome announced politely, and a
  refused write that leaves the value selectable. The same control, the same
  glyph and the same word are taken whole.
- `scroll-area` is the scrollport: a region with a name and a tab stop only
  while the code overflows, the platform's scrollbar, and the mask at the
  overflowing edge. This family's body _is_ a `scroll-area`, worn as
  `data-ui`, and writes no measure of its own.
- `tabs` is the answer to Mantine's `CodeHighlightTabs` and Docusaurus's
  language tabs: one `code-block` per panel.
- `kbd` and `prose`'s inline `code` are the answer to Carbon's `inline`
  snippet: a span in running text is typography, not a block.

## 3. Differentiators

| Capability                                                        | Source                                           | What this library does with it                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The scope palette is a token scale, in three schemes              | Shiki's `transformerStyleToClass`; Prism's standard token names | Twelve scope tokens in the component layer — `--slotted-code-comment`, `-keyword`, `-string`, `-number`, `-function`, `-type`, `-variable`, `-property`, `-punctuation`, `-tag`, `-attribute`, `-constant` — each measured against the block's ground at 4.5:1 in `light` and `dark` and 7:1 in `high-contrast` by the theme's contrast test. The five tones cannot give twelve hues that read apart from each other on one ground, which is the bar `upload`'s file-kind scale cleared. |
| A highlight that arrives late shifts nothing                      | none — Mantine renders plain then re-renders     | The line grid is laid out from the text; tokens are spans inside it. Measured in the harness: the same height before and after.                                                                                                                                                                                                                                                 |
| The copy is the code, not the DOM                                 | Carbon copies `copyText ?? children`; the rest copy the DOM's text | A selection copies what is selected; the control copies `code` with removed lines dropped. A reader never pastes a line number or a diff marker.                                                                                                                                                                                                                                 |
| The scroll region has a name                                      | none of the four frames                          | `scroll-area`'s wiring, so a keyboard reader arriving at a wide block hears "Code, region" — or the filename — rather than nothing.                                                                                                                                                                                                                                              |
| Wrapped continuations keep the indent                             | none                                             | `text-indent` and `padding-inline-start` from the measured leading whitespace of the line, so a wrapped block still reads as code rather than as prose that lost its shape.                                                                                                                                                                                                       |
| Three schemes, three densities, and the fence `prose` already draws | the foundation                                   | One fence in two families, agreeing in every measure; the density scale moves the inset and the gutter and not the type, because code at `dense` is still read one character at a time.                                                                                                                                                                                       |
| Defaults set once                                                 | the DI                                           | `provideSlCodeBlockDefaults({ highlight, lineNumbers, labels })` and `CodeBlockDefaultsProvider`, so an application that has loaded Shiki once hands the highlighter to every block on the page in one place, which is Mantine's `CodeHighlightAdapterProvider` in both bindings.                                                                                              |

## 4. Gaps

| Gap                                                            | Who handles it                     | What this family does                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A line ten thousand characters long                            | nobody says                        | `white-space: pre` and the scrollport hold it; under `wrap`, `overflow-wrap: anywhere` breaks an unbroken token rather than letting it escape the box. Measured in the harness at 240 pixels.                                                                                                                                                       |
| Ten thousand lines                                             | nobody                             | The tokens are rendered per line in one pass and the gutter is a counter, so nothing is measured per line; `maxLines` bounds what is painted at once through the scrollport. Virtualising is refused — a block that is not all in the DOM is not copyable by selection.                                                                              |
| An empty string                                                | nobody                             | One empty line with its number, so the frame is the same size as a block of one line, and `data-empty` for a stylesheet that wants to say so.                                                                                                                                                                                                       |
| Code that has not arrived                                      | nobody                             | `loading`: the frame at the height `collapseAfter` or six lines would give, `aria-busy`, no copy control, `skeleton` lines inside — not a spinner, which is what the briefing's `loading-overlay` boundary keeps off a region that has no content yet.                                                                                                |
| A hostile string                                               | React and Angular escape text; an engine that returns HTML does not | The family takes tokens, never HTML: `CodeLine[]` is text in spans, so an engine's output is never written with `innerHTML`, and a `<script>` in a code sample is drawn as the six characters it is.                                                                                                                                                 |
| Right-to-left code in a right-to-left page                     | `prose` decided it for the fence   | `direction: ltr` on the block, inherited from `prose`'s rule, because the order of the characters is what the code means; the header keeps the page's direction, so the title reads in the reader's language and the code in its own.                                                                                                                 |
| The reader copies with the block's own selection               | Carbon's `role="textbox"` was an answer to it | Selecting inside a `scroll-area` region works as in any text; `user-select: none` on the gutter and on the markers keeps them out. Nothing else is needed, and a role is not.                                                                                                                                                                       |
| Print                                                          | nobody                             | `@media print`: wrap on, the scrollport released, the header and the copy control kept, the collapse released so the paper holds the whole block.                                                                                                                                                                                                    |
