# Table filter operands capability inventory

The subject is three operands the column filter could not draw when it was built
on 10 September: a time, a date-time, and the two controls that replace a pair of
`date-picker`s and a checkbox list. `docs/history/designs/2026-09-10-table-filter-capability-inventory.md`
inventoried the filter itself and nothing there is reopened; §5 puts this pass
beside it. The engine at `@slotted/core/filter` and the five typed components are
the ground, and `docs/history/designs/2026-09-10-table-filter-design.md` holds
the decisions this pass extends.

Produced from the field before the shipped implementation was reread.

---

## 1. Surveyed

Seven implementations, read on 14 September 2026, chosen so the sources disagree
about the same three questions: whether a time of day is a filter kind, how a
date-time compares when the operand has less precision than the value, and what
a set operand becomes when the list is too long to tick.

| Implementation                          | What it calls this                                                                                                                                  | Read at                                                                                                                                                                                                  |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MUI X Data Grid                         | column type `dateTime` = `getGridDateOperators(true)`: `is`, `not`, `after`, `onOrAfter`, `before`, `onOrBefore`, `isEmpty`, `isNotEmpty`; `singleSelect` operator `isAnyOf` with a multiple-value autocomplete; `between` as a custom multiple-values operator | `mui.com/x/react-data-grid/filtering/customization/`; `github.com/mui/mui-x/blob/master/packages/x-data-grid/src/colDef/gridDateOperators.ts`                                                             |
| PrimeReact `FilterService`              | match modes `dateIs`, `dateIsNot`, `dateBefore`, `dateAfter`; no time mode                                                                          | `github.com/primefaces/primereact/blob/master/components/lib/api/FilterService.js`                                                                                                                       |
| AG Grid                                 | Date Filter: `equals`, `notEqual`, `lessThan`, `greaterThan`, `inRange`, `blank`, `notBlank`; Set Filter: virtualised list with a mini filter        | `ag-grid.com/react-data-grid/filter-date`, `/filter-set` — both answered HTTP 403 today; cited from the 10 September reading recorded in the previous inventory                                            |
| KendoReact Grid                         | filter types `numeric`, `text`, `date`, `boolean`; `filterOperators` narrows each type; no `datetime` and no `time` type                            | `telerik.com/kendo-react-ui/components/grid/filtering`                                                                                                                                                   |
| DevExtreme DataGrid                     | `dataType: 'datetime'`; filter row `between` with two editors; header filter grouping date values by year, month and day, with `allowSearch`         | `js.devexpress.com/React/Documentation/Guide/UI_Components/DataGrid/Filtering_and_Searching/`                                                                                                             |
| Ant Design Table v6.6                   | `filterDropdown`, `filterSearch`, `filterMultiple`, `filterMode: 'tree'`; no typed date filter, a date filter is a custom `filterDropdown`           | `ant.design/components/table`                                                                                                                                                                            |
| Microsoft Excel AutoFilter              | Date Filters with relative items (Today, This Week, Next Month); a column of times receives Number Filters, because a time is a serial fraction     | `support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e`, from the 10 September reading                                                                 |

Three answers the sources give:

- **A time of day is not a kind anywhere.** MUI X and DevExtreme ship a
  date-time and no time; Kendo, PrimeReact and Ant ship a date and no more;
  Excel filters a time column as a number. A column of opening hours, shift
  starts or cut-off times is filtered nowhere as what it is.
- **Precision is decided by the library, not by the operand.** MUI X zeroes
  seconds when `showTime` is on, so a value at 09:14:30 `is` 09:14 and a second
  can never be filtered on. PrimeReact compares `toDateString()` for `dateIs`
  and `getTime()` for `dateBefore`, so equality is a day and order is an
  instant, in the same match-mode family. AG Grid compares against the filter
  date at local midnight and drops time altogether.
- **A big set becomes a search, a page or a chip list.** AG Grid virtualises
  the list and searches it; DevExtreme pages it and groups dates into a tree;
  MUI X's `isAnyOf` is an autocomplete that holds chosen values as chips; Ant
  hands the consumer `filterDropdown` and steps aside.

## 2. Table stakes

Every capability two or more of the seven ship.

| Capability                                                                    | Who ships it                                               | Verdict                | Reason                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A date-time kind with the date operators                                     | MUI X (`dateTime`), DevExtreme (`datetime`), PrimeReact (`dateBefore` on `getTime()`) | adopt                  | `datetime` kind: `is`, `isNot`, `before`, `after`, `between`, `empty`, `notEmpty` over a `PlainDateTime`; `TableDateTimeFilter` in both bindings with `datetime-picker` as the operand.                                                                                                       |
| Blank and not blank on a date-time                                           | MUI X, AG Grid                                             | adopt                  | The two zero-operand operators every kind already has.                                                                                                                                                                                                                                       |
| Comparison at a precision coarser than the value                             | MUI X (seconds zeroed), PrimeReact (day), AG Grid (day)    | adapt                  | The operand's own precision decides, not the library's: an operand written to the minute is compared against the value's minute, for every operator — the rule the `date` kind already applies to a timestamp, which is reduced to its day before `is`, `before` and `after` alike. §3. |
| Order comparisons on a date-time as an instant                               | MUI X, PrimeReact, DevExtreme                              | adapt                  | Compared as wall-clock `PlainDateTime`, never as an instant — the wave 7 decision in `docs/build-briefing.md`. | The operator list narrowed per column                                        | Kendo (`filterOperators`), AG Grid (`filterOptions`), MUI X (`filterOperators`) | adopt                  | Shipped as `operators` on each typed component; the two new components take it unchanged.                                                                                                                                                                                                    |
| `between` drawn as two inputs                                                 | AG Grid (`inRange`), DevExtreme, MUI X (custom example)    | adapt                  | The `date` kind draws one `date-range-picker`, because the family now has one; `datetime` and `time` keep two pickers until `datetime-range-picker` and `time-range-picker` land (wave 8, `docs/process/build-order.md`). The descriptor stays `{ operator: 'between', value, end }` for all three.        |
| Search inside a long set list                                                 | AG Grid (mini filter), DevExtreme (`allowSearch`), Ant (`filterSearch`) | adopt                  | Shipped past eight values; unchanged.                                                                                                                                                                                                                                                        |

| A typed set operand constrained to known values                              | MUI X (`valueOptions` only), AG Grid (list only)           | adapt                  | With `options` given, a typed value outside them is refused through `tags-input`'s `validate` and announced by that family; without `options` any value is admitted, because a list too long to tick is often a list the page does not hold in full.                                           |

## 3. Differentiators

| What                                                     | Against the field                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A `time` kind                                            | None of the seven filters a time of day as a time. Here `time` is a kind with `is`, `isNot`, `before`, `after`, `between`, `empty`, `notEmpty` over a `PlainTime`, and `TableTimeFilter` draws `time-picker`, which offers the same list of options the column's own field offers.                                                                              |
| Precision follows the operand                            | MUI X decides seconds do not exist; PrimeReact decides `is` means a day and `before` means a millisecond. Here the ISO text the reader wrote carries its own precision — `09:14` is a minute and `09:14:30` is a second — and the row value is truncated to it before every comparison, so `after 09:14` starts at 09:15:00 the way `after 10 September` starts on the 11th. |
| A wall-clock value, never an instant                     | Every surveyed implementation compares `Date.getTime()`, so a filter for "after 02:30 on 29 March" is answered differently on two machines in two zones. The descriptor holds `PlainTime` and `PlainDateTime` ISO text and the predicate reduces a `Date` row value to wall-clock in one stated zone, which is the rule the whole date chain already keeps.       |
| A `time` range that crosses midnight                     | No surveyed implementation has a time kind, so none answers it. `between 22:00 and 02:00` is the overnight window, not an empty set and not the daytime window the pair-ordering rule for numbers would produce. §4.                                                                                                                                             |
| One range control for `between`                          | AG Grid, DevExtreme and MUI X stack two inputs. `date-range-picker` draws one control that says the run's length while it is drawn and refuses an inverted pair before it reaches the descriptor.                                                                                                                                                                |
| Chips for a long set, without a second vocabulary        | MUI X's `isAnyOf` is a separate operator from `is`; here the operator stays `anyOf` / `noneOf` and only the control changes, so a saved view written by the list operand is read by the tags operand and back.                                                                                                                                                  |
| Typed per kind in both bindings                          | `TimeFilter` and `DateTimeFilter` are two more members of the discriminated union, each with a `model<… \| null>()` in Angular and a `value` in React that needs no narrowing.                                                                                                                                                                                  |
| The codec and the summary already speak the new kinds   | `serializeFilter` and `parseFilter` carry the ISO text unchanged and `describeFilter` formats it through the caller's formatter, so `filter-bar`'s chips and a bookmarked URL learn nothing new.                                                                                                                                                                 |

## 4. Gaps

What no surveyed implementation handles well and a listing screen still hits.

| Gap                                                                                       | What this family does                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A time `between` whose start is later than its end                                        | Read as a window that crosses midnight: `between 22:00 and 02:00` matches 23:00 and 01:00. The number and date kinds order the pair, because 100 then 10 has one sensible reading; 22:00 then 02:00 has a different one. `describeFilter` says the pair in the order it was written. |
| An operand written to the minute against a value carrying seconds                         | Truncated to the operand's precision before every comparison; a value at 09:14:30 `is` 09:14, is not `after` 09:14, and is `between` 09:00 and 09:14.                                                                                                                                |
| A date-time operand with one half missing                                                 | `datetime-picker` reports the incomplete half and the condition is inactive until both halves exist, which is the engine's one rule for a missing operand. Nothing reaches the consumer on Apply.                                                                                     |
| A `Date` row value in a time column                                                       | Reduced to its wall-clock time in the predicate's `timeZone`, the way a `Date` in a date column is reduced to its day.                                                                                                                                                               |
| A colon in the query string                                                               | `toFilterParams` percent-encodes through `URLSearchParams`, and `parseFilter` refuses a malformed `HH:MM` or `YYYY-MM-DDTHH:MM` with `null` rather than throwing.                                                                                                                      |
| A typed set value the column does not hold                                                | With `options`, refused and announced by `tags-input`; without, admitted. A reader who pasted a comma-separated list gets every value split, because `tags-input` already splits on paste.                                                                                            |
| Twenty chips in a seventeen-rem panel                                                     | `tags-input` wraps and the panel grows downward inside the layer's available height; the chosen values stay reachable and removable by keyboard, which a checkbox list of twenty ticked values already was.                                                                            |
| A saved view written with the list operand, opened with the tags operand                  | Read unchanged: `operand` is how the values are chosen, not what they are.                                                                                                                                                                                                           |
| A `between` on a date whose reader picks the end first                                    | `date-range-picker` accepts the run in either order and the descriptor receives `value` ≤ `end`; the announced length is the same.                                                                                                                                                   |

## 5. What shipped, and the delta

Five kinds, five components per binding, a `date` operand that is one
`date-picker` per operand and a set operand that is a checkbox list.

| Capability                                   | Shipped               | The field                          | This pass                                                                                   |
| -------------------------------------------- | --------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------- |
| `datetime` kind and component                | no                    | yes ×3                             | added                                                                                       |
| `time` kind and component                    | no                    | none                               | added                                                                                       |
| `between` on a date as one range control     | two `date-picker`s    | two inputs                         | one `date-range-picker`, with `presets`                                                     |
| Set operand as chips                         | no                    | yes ×2                             | added as `operand="tags"`, list kept as the default                                         |
| Precision rule for `is` on a date-time       | —                     | fixed by the library               | follows the operand                                                                         |
| Overnight time window                        | —                     | none                               | `between` wraps at midnight for `time`                                                      |
| Descriptor, predicate, codec, summary        | yes                   | —                                  | unchanged in shape; two kinds added to the union                                            |

Nothing shipped is dropped. A consumer's `DateFilter` written with two dates is
the same object whether two pickers or one range picker produced it, and a
`SetFilter` is the same list whether it was ticked or typed.
