# `tags-input` — capability inventory

Wave 8, round 11. Read on 2026-09-14, before any of this family's code was
written. `docs/component-features.md` §6 gives `MultiSelect / Tags Input` one
paragraph, and `multi-select` (wave 6, item 5) has already answered every line
of it — chips, creation, limit, duplicates, reorder, paste, `Backspace`,
overflow. So the first question this inventory answers is not "what does a tags
input do" but **why a second family**, and the survey is where the answer is.

`docs/product/prd.md` names neither this family nor a chip; nothing there narrows
it. `docs/process/build-schedule.md` round 12 asks this family for one thing by name:
the operand of `table`'s set filter "when the list of values is too large for
checkboxes" — a reader typing identifiers, not choosing them.

## 1. Surveyed

Nine sources, read 2026-09-14. The field splits cleanly in two, and the split
is the boundary this family sits on:

- **A text field that produces values.** Zag, Ark, Angular Material's chip
  grid, UI5's `MultiInput`, emblor, and the platform's own
  `<input type="email" multiple>`. There is no popup; what the reader types _is_
  the value.
- **A listbox that produces a set.** Mantine's `TagsInput`, Fluent's
  `TagPicker`, Base UI's `Autocomplete multiple`. The typed text is a query and
  the value is a key. This library already ships this half as `multi-select`.

One specification sits under the first group and was read the same day:

- [Grid Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/grid/), the **layout
  grid** half. It names this control — "a list of recipients for a message may
  be a grid where each cell contains a link that represents a recipient. The
  grid may initially have a single row but then wrap into multiple rows as
  recipients are added" — and its keyboard table is the chip row's. The
  combobox pattern was **not** read for this family, because the input here is
  a text box and opens nothing.

Inside this repository, three families were read for the boundary and not for
the survey:

- `multi-select` ships the listbox half in full. Its design document draws its
  own boundary by the control element; this family draws it by **what the
  value is** — see §5.
- `tag` deferred the editable chip and the chip-as-form-control to this family
  by name (`docs/history/designs/2026-09-02-tag-family-design.md`);
  `multi-select` took the editable chip. The chip a reader removes here is
  still `tag`'s, worn as `data-ui`.
- `text-field` owns the frame every control on a form shares; this family's
  frame is the same arithmetic.

## 3. Differentiators

The best surveyed implementation of the text half is Zag's machine, and the
best of the enterprise half is UI5's `MultiInput`. What neither has, and what
this library can offer because of what it already owns:

| Differentiator                                          | What it is                                                                                                                                                                                                                                                                                                                                                                                             | Why only here                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **An invalid value is held and shown, not dropped**     | `invalidValues: 'keep' \| 'refuse'`, default `keep`. A value `validate` refuses still becomes a chip: it wears `tag`'s `danger` tone with the alert mark, carries `data-invalid` and `aria-invalid`, its message is its description, the root is `data-invalid`, the Angular `Validator` reports it, and the visible input's `setCustomValidity` blocks the native submit. `refuse` is `multi-select`'s behaviour — reported, not added — for a filter operand where a bad value has nowhere to go. | Every surveyed implementation drops what fails `validate` — Zag fires `onValueInvalid` and shows nothing. A recipients field that silently drops `jhon.company` has told the reader John was invited. The value the reader typed stays where they can see it and fix it, which is what Gmail and Outlook both do and no library does. |
| **The browser validates, in the reader's language**     | With no `validate`, each value is judged by the input's own constraints — `type="email"`, `pattern`, `minlength`, `maxlength` — through a detached input carrying the same attributes, and the chip's message is `validationMessage`.                                                                                                                                                                | The platform's `<input type="email" multiple>` already knows the email grammar and already has the sentence "Please include an '@'…" in forty languages. No surveyed library reaches for it; each ships a regex or asks the consumer for one.                                                                                                                                                              |
| Reorder by keyboard, direction-aware                    | `Alt` + arrow moves the chip one place along the row; `Alt`+`Home`/`End` to either end; announced.                                                                                                                                                                                                                                                                                                     | `multi-select`'s decision, inherited. None of the nine ships keyboard reorder.                                                                                                                                                                                                                                                                                                                             |
| Arrow keys that follow the writing direction            | `ArrowRight` moves toward the end of the row in `ltr` and toward the start in `rtl`.                                                                                                                                                                                                                                                                                                                   | Zag, Material and UI5 bind the arrows literally.                                                                                                                                                                                                                                                                                                                                                           |
| A collapsed row that opens where the reader is          | Under `overflow="collapse"` the row is one line and a `+N` at rest, and wraps to every chip while the control has focus. There is no popup to hold the hidden values, and none is needed.                                                                                                                                                                                                             | UI5's tokenizer is the only surveyed control that does this, and it does it with a popover as well. Here the count is `createCollapse`'s measurement, so it cannot disagree with the screen.                                                                                                                                                                                                              |
| The list on the clipboard                               | `Ctrl+C` on the empty input copies every value, joined by the first delimiter and a space.                                                                                                                                                                                                                                                                                                             | UI5 copies one token. A list the reader built is a list they want to paste into an email, a spreadsheet, or another instance of this family — and the join is the one the paste path splits.                                                                                                                                                                                                             |
| Three schemes and three densities                       | The chip is a `tag`, and `tag.css` already floors its remove control at `--slotted-target-min` per density.                                                                                                                                                                                                                                                                                            | Every surveyed implementation has one palette and one density.                                                                                                                                                                                                                                                                                                                                             |

## 4. Gaps

What no surveyed implementation handles well and a real product still hits.

## 5. What this family is against `multi-select`

`multi-select` draws its boundary by the control element. This family cannot,
because the control is the same shape — a frame around a real input, chips
inside it. The boundary is **what the value is**.

|                            | `multi-select`                                                    | `tags-input`                                                                                       |
| -------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| The value                  | an ordered set of **keys**, resolved to labels by a collection    | an ordered list of **texts**; the text is the label                                                |
| Where a value comes from   | a listbox popup, and the typed text when `creatable`              | the typed text, always                                                                             |
| The input                  | `role="combobox"`, `aria-expanded`, `aria-activedescendant`       | a text box. No role, no popup; `list` passes through to the browser's own datalist                 |
| A value that fails         | refused and reported                                              | **held, marked, described**, and reported; `refuse` is an axis                                     |
| Who validates              | `validateValue`, the consumer                                     | `validate`, or the input's own constraints through the browser                                     |
| What is composed           | positioner, presence, portal, dismissable-layer, collection       | none of those. `@slotted/core/tags` for the arithmetic, plus overflow, measure, focus, clipboard   |
| The `selection` capability | held — the set is a selection over a collection                   | not held — there is no collection. The list and the text are both `value`                          |

A consumer with known options reaches for `multi-select`. A consumer whose
reader brings the values — addresses, identifiers, keywords, hostnames — reaches
here, and gets a control that says which of those values is wrong instead of
losing it.

## 6. Exit

Nothing in §6 of the feature guide is unanswered; every capability two
surveyed implementations ship has a verdict; each decline names the family or
the lines of consumer code that replace it; each defer names the module or the
family. The one capability adopted on a single source — copying — is adopted
because the value here is text, and it is recorded above as a decision rather
than as table stakes.
