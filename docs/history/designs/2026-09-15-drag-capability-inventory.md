# `drag` — capability inventory

Wave 9, round 16. Read on 2026-09-15, before any of the module's code was
written. `@slotted/core/drag` is the `infra` line of `docs/process/build-order.md`
wave 9: a module of `packages/core` with no stylesheet, no harness fragment in
`packages/styles` and no reference page. It is the drag foundation three
inventories deferred to — `listbox` (l. 125), `tree` (l. 101), `tags-input`
(l. 90) — and the one `data-grid` needs for its columns.

The scope paragraph is the floor:

> Pointer, touch e teclado; pré-visualização, alça, zonas válidas, auto-scroll,
> cancelamento por Escape e anúncio pelo `live-announcer`. O evento carrega
> itens, origem, destino, posição e operação permitida; o modelo de dados é o do
> consumidor e não a geometria do DOM. A alternativa por teclado (pegar, mover
> com setas, soltar) é construída primeiro e o ponteiro deriva dela.

`docs/component-features.md` §3 adds nothing to it, and §2.5 names the three
states a consumer paints: `dragging`, `drop-target`, `drop-invalid`. All three
are already in `specs/contract.schema.mjs`; `upload` put the third there.

### The pattern, transcribed

There is no APG pattern for drag and drop, and there is no ARIA state for it:
`aria-grabbed` and `aria-dropeffect` are deprecated, so nothing in the
accessibility tree says "this is being dragged". What survives is three rules
from three places.

**WCAG 2.2 SC 2.5.7.** A drag is a gesture; the outcome it produces has to be
reachable without one. This is the sentence that orders the keyboard model
first: the keyboard session is the definition of what a drag does, and the
pointer is a second way of driving the same session.

**APG rearrangeable listbox.** The one official example of moving an item:
modifier plus arrow moves it one place, `Home`/`End`-style ends exist through
the toolbar, every move is reported in a `polite` region as a sentence with a
position and a count, and the buttons that do it carry `aria-keyshortcuts`.
`tags-input` and `multi-select` already implement this shape (`Alt`+arrow,
announced), and the module has to be able to express it as one call so those
two families can move onto it without changing what the reader presses.

**react-beautiful-dnd / dnd kit keyboard sensor.** The other official-by-usage
shape: a **session** — pick up (`Space`/`Enter`), move the drop position with
arrows, drop (`Space`/`Enter`), cancel (`Escape`) — with an instruction string
on the draggable and an announcement per step. This is the "pegar, mover com
setas, soltar" the scope names, and it is the one that scales to a drop onto a
folder, a move into another list, and a grid.

The module holds the session; the one-call move is the session compressed.

## 3. Differentiators

| Capability                                                        | Where it comes from                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The keyboard is the definition; the pointer is a driver           | Three of the four libraries added the keyboard sensor after the pointer one, and CDK never did. Here the session — positions, validity, operation, announcement — is written once for the keyboard, and the pointer's only job is to turn a point into the same position. A pointer drop and a keyboard drop are the same event to the consumer. |
| One event for every consumer                                      | `data-grid` columns, `listbox` rows, `tree` nodes, `tags-input` chips and `dashboard-grid` cells all receive `{ items, source, target, operation, reason }`, and none of them learns a second vocabulary. `moveBy` lets `tags-input` keep `Alt`+arrow while emitting it.                                                                     |
| A reason on the drop                                              | `docs/state-and-events.md`: a request carries why. `keyboard`, `pointer` and `programmatic` are in the closed vocabulary already, and a consumer persisting the reader's own reorder can ignore the programmatic one.                                                                                                                       |
| The announcer that already exists                                 | `live-announcer` dedupes, spaces and clears; the module writes sentences and nothing else. dnd kit and React Aria each ship a second live region for the drag.                                                                                                                                                                             |
| Direction from the document, not from a prop                      | Horizontal arrows read `direction` from the container's computed style, so a `dir="rtl"` subtree reorders the way its text reads with no configuration — the rule `tags-input` learned.                                                                                                                                                    |
| A capture the reviewer can drive                                  | `tools/harness/core.mjs` builds a page that runs the module against the theme with no framework, so the keyboard session, the pointer drag, the invalid zone and the auto-scroll can be exercised at the gate. `positioner` had only its tests; the gate had nothing to open.                                                              |

## 4. Gaps

| Situation                                          | What the module does                                                                                                                                                                                                                                                                                             |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The list re-renders mid-drag                       | `items()` is a function read at pick-up and at every move, so an item removed or added by the application while a drag is open changes the positions rather than the module's memory of them. A source that disappears cancels the drag.                                                                          |
| Nowhere to drop                                    | Every container refuses, or the only container is the source with one item: `pickUp` still succeeds, `move` finds no position, and `messages.nowhere` says so. `drop` on no valid target is a cancel, not a silent no-op, and `onDragEnd` says `dropped: false`.                                                   |
| Two thousand rows                                  | Position resolution for the keyboard is an index, not a scan; for the pointer, a container is chosen by its own rect and the index by the item rects the family provides, which a virtualised family provides for the rows it rendered. Nothing measures a row that is not on screen.                              |
| Two pointers                                       | A second `pointerdown` while a session is open is ignored; the session belongs to the `pointerId` that opened it.                                                                                                                                                                                                 |
| The tab goes away                                  | `visibilitychange` to hidden and window `blur` cancel, so a reader coming back does not find an item stuck to nothing.                                                                                                                                                                                             |
| A drag started on a handle inside a scrolling list on a phone | The hold delay keeps the page scrolling under a swipe; once the hold has elapsed, `touchmove` is prevented and the list stops scrolling under the finger, and auto-scroll takes over near the edge.                                                                                                       |
| A hostile or translated label                      | Every announcement is built by the consumer's `messages` functions from labels the consumer supplies, and reaches the region through `textContent`. The module never reads `innerText` to name an item.                                                                                                             |
| Same-container move onto the slot it left          | Under `move`, the gap before and the gap after the source are the same list; the keyboard treats them as one position and never announces a move that changes nothing, and a pointer released there ends the session as a cancel — `docs/state-and-events.md`: a request for the value the consumer already holds is not emitted. |
