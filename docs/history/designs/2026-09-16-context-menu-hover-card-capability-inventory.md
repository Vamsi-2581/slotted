# Context menu and hover card — capability inventory

Two families, one session, one decision: each is the core of a delivered family
— `menu`, `popover` — behind a trigger the core does not have. The inventory is
taken from the field before any code, as `.claude/skills/component/references/capability.md`
requires, and the delta against what the two cores already ship is named in §5.

## 1. Surveyed

Every row was read on 2026-09-16.

Two names hide one capability. Radix's `ContextMenu` and Base UI's `ContextMenu`
are Ark's `Menu.ContextTrigger` and the CDK's `cdkContextMenuTriggerFor`: the
first two copy the whole menu under a second name, the last two add one trigger
to the menu they already have. Radix's `HoverCard` is Base UI's `PreviewCard`
and Ark's `HoverCard`.

The four context-menu implementations agree on the gesture and disagree on the
anatomy, which is the decision this session settles (§5).

## 2. Table stakes — `context-menu`

| Capability                                                                          | Who ships it                                     | Verdict                  | Reason                                                                                                                                                                                                                                             |
| ----------------------------------------------------------------------------------- | ------------------------------------------------ | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Opens on the `contextmenu` event (secondary click)                                  | Radix, Base UI, Ark, CDK                         | adopt                    | The gesture the family exists for. The native menu is suppressed with `preventDefault` while the family is enabled.                                                                                                                                 |
| The surface is positioned at the pointer's point                                    | Radix, Base UI, Ark, CDK                         | adopt                    | A virtual anchor — a rectangle at the point — handed to `positioner`, which `PositionerAnchor` already accepts. `menu` gains an `anchor` that wins over its trigger; recorded in §5.                                                                |
| Long press on touch and pen opens it                                                | Radix, Base UI, Ark (≈700 ms), React Aria        | adopt                    | `longPress` axis, default on; `longPressDelay` default 500 ms, the value `tooltip` already holds as `touchDelay`. Movement past 10 px, `pointerup` or `pointercancel` before the delay cancels it.                                                   |
| Every capability of the menu: items, checkbox and radio items, groups, separators, submenus, shortcuts, typeahead, `loop`, `closeOnSelect`, disabled items, `mount` | Radix, Base UI, Ark, CDK | adopt — holds `menu`     | The surface is `menu` unchanged, as `menubar` holds it. Nothing is re-exported: a consumer imports `MenuContent` and its items from the menu family.                                                                                                |
| Controlled and uncontrolled `open`, request with a reason                           | Radix, Base UI, Ark                              | adopt                    | `open` / `defaultOpen` / `onOpenChange`, the menu's own model surfaced through the family's props in React and through `sl-menu [(open)]` in Angular.                                                                                                |
| The trigger reflects the open state for styling                                     | Radix (`data-state`), Base UI (`data-popup-open`), Ark (`data-state`) | adopt      | `data-open` on the root, which is the target area.                                                                                                                                                                                                 |
| Re-opening at a new point while open                                                | Radix, Base UI                                   | adapt                    | Both close and reopen, two requests for one gesture. Here the anchor moves and the surface repositions; no request is emitted, because `open` did not change.                                                                                       |
| Focus returns after the menu closes                                                 | Radix (`onCloseAutoFocus`), Base UI, CDK         | adapt                    | To the element that held focus when the menu opened, and to the target when nothing did. Radix returns focus to a `span` that cannot take it. `menu` gains `finalFocus`, which its own design (§4, note 3) already promised.                          |
| `disabled` — the family never opens                                                 | Base UI (`Root disabled`), Ark                   | adopt                    | A disabled context menu lets the browser's own menu through, because suppressing both leaves the reader with nothing.                                                                                                                              |
| `modal`, with a backdrop                                                            | Radix (default `true`), Base UI (`Backdrop`)     | decline — defer to `dialog` | The reason `menu` recorded: `docs/component-features.md` §8 gives the modal surface to Dialog, and `applyInert` would inert the target itself.                                                                                                       |
| `alignOffset` of 2 px from the pointer                                              | Base UI                                          | decline                  | Windows and macOS put the surface's corner on the point. A gap between the pointer and the surface is a gap the pointer has to cross, and the first item is highlighted by movement rather than by arrival, so nothing is gained by it.              |
| An element rather than the pointer as anchor                                        | Base UI (`Positioner anchor`)                    | adopt                    | The keyboard case needs it: a menu opened by `Shift+F10` hangs from the focused target, not from wherever the pointer last was. The same `anchor` on `menu` takes an element for a consumer anchoring a menu to a row.                                |
| A `render` prop for the trigger / a directive on the consumer's element             | Radix (`asChild`), Base UI (`render`), CDK (directive) | adopt              | React gets `render`; Angular gets `slContextMenuTriggerFor` on the consumer's own element.                                                                                                                                                         |
| Application defaults set once                                                       | Radix (none), Base UI (none), this repository (`menu`, `popover`, `tooltip`) | adopt | `ContextMenuDefaultsProvider` and `provideContextMenuDefaults()` for `longPress`, `longPressDelay`, `disabled`; the menu's own defaults keep governing the surface.                                                                                  |

Keyboard opening — `Shift+F10` and the `ContextMenu` key on the focused target —
is shipped by none of the four libraries. It is adopted anyway: it is the
platform convention on Windows, `docs/component-features.md` §8 names it, and a
menu that only a pointer can open is a menu a keyboard reader cannot reach.

## 3. Table stakes — `hover-card`

| Capability                                                              | Who ships it                                                          | Verdict                    | Reason                                                                                                                                                                                                                                        |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Controlled and uncontrolled `open`, request with a reason               | Radix, Base UI, Ark                                                   | adopt                      | `open` / `defaultOpen` / `onOpenChange`; `model()` in Angular.                                                                                                                                                                                 |
| Opens on hover, after `openDelay`                                       | Radix (700), Base UI (600), Ark                                       | adopt                      | Default 600 ms, the number `tooltip` already holds and the one Base UI reached. Two hover-opened families with two warmups would read as two libraries.                                                                                       |
| Closes after `closeDelay` once the pointer has left trigger and card    | Radix (300), Base UI (300), Ark                                       | adopt                      | Default 300 ms, two of three; twice the tooltip's, because a card is farther and larger than a hint.                                                                                                                                          |
| Opens on focus of the trigger                                           | Radix, Base UI, Ark                                                   | adapt                      | On `:focus-visible` only, and with no delay — the two rules `tooltip` settled. A press that focuses a link is a navigation, not a request for its preview.                                                                                    |
| Stays open while the pointer is over the card                           | Radix, Base UI, Ark                                                   | adopt                      | WCAG 1.4.13 Hoverable.                                                                                                                                                                                                                        |
| The trigger renders an `<a>`                                            | Radix, Base UI                                                        | adopt                      | With `render` for a button or another family's root. The trigger is the family's root part (§5).                                                                                                                                             |
| The trigger reflects the open state                                     | Radix (`data-state`), Base UI (`data-popup-open`)                     | adopt                      | `data-open` on the root.                                                                                                                                                                                                                      |
| Portal, side, align, offsets, collision, arrow, `hideWhenDetached`, transform origin, anchor size and available space as custom properties | Radix, Base UI, Ark | adopt — holds `popover` | The card is `popover` unchanged behind a hover trigger. Nothing is re-exported.                                                                                                                                                              |
| Escape dismisses                                                        | Radix, Base UI, Ark                                                   | adopt                      | WCAG 1.4.13 Dismissible; `dismissable-layer` through `popover`.                                                                                                                                                                              |
| A press outside dismisses                                               | Radix (`onPointerDownOutside`), Base UI, Ark                          | adopt                      | Through `popover`.                                                                                                                                                                                                                            |
| The card does not take focus when it opens                              | Radix, Base UI, Ark                                                   | adopt                      | `autoFocus` is forced off. A card that stole focus from the link under the pointer would be a dialog wearing the wrong trigger.                                                                                                                |
| The content is not keyboard-reachable                                   | Radix ("inaccessible to keyboard users"), Base UI ("not keyboard navigable") | adapt               | A `navigable` axis. Off, the field's behaviour. On, `Tab` from the open trigger enters the card and `popover`'s focus guards return focus to the trigger, which does not reopen. `docs/process/build-order.md` asks for "conteúdo navegável opcional". |
| Touch                                                                   | Radix (nothing), Base UI ("not touch navigable")                      | adapt                      | A tap on a closed trigger opens the card and does not follow the link; a tap on an open trigger follows it. `docs/process/build-order.md`: "Toque abre por clique".                                                                                    |
| One card shared by many triggers, with a payload                        | Base UI (`handle`, `payload`)                                         | adapt                      | Many `HoverCardTrigger`s inside one `HoverCard`: the trigger that starts an opening registers itself as the anchor. The payload is the consumer's two lines — `onOpenChange` receives the event whose `currentTarget` is the trigger.        |
| `Viewport` — cross-fading content between triggers                      | Base UI                                                               | decline                    | It exists for the shared-card case above and animates content the consumer owns. The consumer who wants it wraps their content in `presence`; a card that changes content while open repositions through `reposition()` on the handle.       |
| Application defaults set once                                           | Radix (none), Base UI (none), this repository                         | adopt                      | `HoverCardDefaultsProvider` and `provideHoverCardDefaults()` for `openDelay`, `closeDelay`, `navigable`, `arrow`; the popover's own defaults keep governing the panel.                                                                        |

## 4. Differentiators

| Capability                                                                             | Family         | Why this library can offer it                                                                                                                                                                                                                  |
| -------------------------------------------------------------------------------------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A menu opened from the keyboard hangs from the target                                  | `context-menu` | None of the four libraries opens from the keyboard at all. The `anchor` that takes a point also takes the target element, so `Shift+F10` puts the surface where the reader is looking.                                                        |
| Focus returns to what had it, not to the trigger                                       | `context-menu` | A target is a region — a row, a card, a canvas — and the focused thing inside it is what the reader was doing. Radix hands focus to a `span` that drops it.                                                                                     |
| `data-pressed` while a long press is running                                            | `context-menu` | The stylesheet turns off `user-select` and the iOS callout for the duration of the press and nothing else, so a target that is text stays selectable at rest.                                                                                  |
| A grace area on the way to the card                                                    | `hover-card`   | `pointer-intent`, written for `menu`'s submenu and promised to this family in its design §5: the card stays while the pointer's own path still points into it. Radix and Ark rely on the close delay alone.                                     |
| Navigable content, with the way out                                                    | `hover-card`   | `popover`'s focus guards already answer what `Tab` does at the end of a portalled layer. The card inherits the answer; the field declares the content unreachable.                                                                              |
| Three schemes, three densities, right-to-left, one stylesheet                          | both           | The surfaces are `menu` and `popover`, so every retuning a theme applies to them reaches the two new families with no second stylesheet to keep in step.                                                                                       |

## 5. The delta against the cores, and the anatomy it decides

What shipped in `menu` and `popover`, what the field ships, and what this
session adds to the cores rather than beside them:

| Core      | Promised                                                                        | Shipped                                        | This session                                                                                                                                                        |
| --------- | ------------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `menu`    | "an anchor that is a point rather than an element, which is adopted here" (inventory l. 117) | The layer is positioned against the trigger node only | `anchor` on `Menu` (React prop) and on `SlMenu` (a signal a trigger directive writes, beside `trigger`). It wins over the trigger for positioning and for nothing else. |
| `menu`    | "`finalFocus` escape hatch; the default destination is the trigger" (design §4, note 3) | Focus always returns to the trigger node       | `finalFocus`, consulted before the trigger on close.                                                                                                                 |
| `popover` | "The consumer's explicit value always wins" (`frameworks.md`)                    | `PopoverContent` writes `role="dialog"` over the consumer's `role` | The consumer's `role` wins; the hover card sets `presentation` when the card is not navigable.                                                              |

Both new families take the shape `menubar` took: **a root the family owns,
holding the core unchanged, re-exporting none of it.** Radix's `ContextMenu`
re-exports sixteen parts and its documentation repeats the dropdown page nearly
line for line; Ark adds one part to the menu it has. The cost of Ark's shape here
is one context per family — the menu has to know its anchor is a point, the
popover has to know it must not take focus — and both are paid in the core
once.

- `context-menu`'s root is the **target area**: the element the reader presses.
  Radix renders a `span`, Base UI a `div`, Ark a `button`; here a `div`, with
  `render` for a row or a card. `menu`'s "trigger is not a part" rule is about a
  *control* that is very often another family's root; a context target is a
  *region* the consumer wraps, and the family's own element is what carries the
  press state the stylesheet needs.
- `hover-card`'s root is the **trigger**, an `<a>` by default, as Radix and Base
  UI render it. It is the one element the family paints — the state while the
  card is showing — and the card itself is `popover`'s.

## 6. Gaps

| Case                                                                           | Family         | Answer                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------ | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Two hundred rows, one menu                                                     | `context-menu` | One `ContextMenu` around the list; `onOpenChange(open, request)` carries the event, and `request.event.target.closest('[data-row]')` names the row. Mounting a menu per row is the shape Base UI's `handle` exists to avoid, and the composition here needs no new API.        |
| A right-click on an item of the open menu                                      | `context-menu` | The browser would draw its own menu over the family's. While the menu is open, `contextmenu` inside the layer is prevented.                                                                                                                                                  |
| A long press that is a scroll                                                  | `context-menu` | Movement past 10 px before the delay cancels the press; `pointercancel` — which the browser fires when it takes the gesture for scrolling — cancels it too.                                                                                                                  |
| The iOS callout and text selection during a long press                         | `context-menu` | `-webkit-touch-callout: none` on the root under `(pointer: coarse)`, and `user-select: none` only while `data-pressed`, so text in a target stays selectable at rest.                                                                                                        |
| A target that is not focusable                                                 | `context-menu` | The keyboard cannot open it and the reference page says so. The family writes no `tabindex`: a row in a grid has roving focus, a canvas has its own, and a `tabindex` written by the family would add a stop the page did not plan.                                          |
| A point near the viewport's corner                                             | `context-menu` | `positioner` flips and shifts, as for every layer; the harness fixes the layer where the engine would place it.                                                                                                                                                              |
| A link that wraps onto a second line                                           | `hover-card`   | Not solved. `getBoundingClientRect` on an inline element spanning two lines is the box around both, so the card may point at the gap between them. Floating UI's `inline()` middleware answers it and `positioner` does not expose it; recorded as a reopening of `positioner`. |
| The preview is still loading                                                   | `hover-card`   | The consumer's `skeleton` inside `PopoverBody`, with `aria-busy` on the content; the card's measure is the popover's `size`, so the box does not jump when the data lands.                                                                                                     |
| Focus returns to the trigger and the card reopens                              | `hover-card`   | Focus put back by the family — after a guard, after Escape — does not reopen: the trigger holds the reopening back until focus leaves it once.                                                                                                                                |
| A hover card on a touch device, on a link the reader meant to follow           | `hover-card`   | The first tap opens and the second follows; the reference page states the cost — one extra tap — beside the alternative, which is a preview no touch reader can ever see.                                                                                                     |
| The pointer parks on the trigger and never moves                               | `hover-card`   | The card opens after `openDelay` and stays: WCAG 1.4.13 Persistent. Leaving the trigger toward anything but the card closes it after `closeDelay`.                                                                                                                             |
