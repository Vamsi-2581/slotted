# Text Field and Textarea — capability inventory

Produced from the field rather than from the family, before any design or code.
`text-field` replaces the deleted `input` family and `textarea` replaces the
deleted family of the same name; both shipped on schema 4 and both are read
side by side with the survey in the last section.

## 2. Table stakes

Every capability two or more of the thirteen ship. `TF` marks a row that
belongs to `text-field`, `TA` to `textarea`, `both` to both.

| Capability                                                          | Family | Who ships it                                                                     | Verdict                          | Reason                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Value with a controlled and an uncontrolled pair                    | both   | Base UI, React Aria, Fluent, Mantine, Shoelace, Angular Material                  | adopt                            | `value` / `defaultValue` / `onValueChange` in React, `model()` plus `ControlValueAccessor` in Angular, both over `@slotted/core/state`.                                                                                                        |
| A change request carrying why it was requested                      | both   | Base UI (`eventDetails.reason`), Fluent (`data`)                                  | adopt                            | `keyboard` for an edit made in the control's own editing surface, `clear` for the clear button. Nothing else can move the value.                                                                                                                |
| Three type steps                                                    | both   | Fluent, Primer, Carbon, Shoelace, Mantine, Radix                                  | adopt                            | `size="sm\|md\|lg"`, reading `--slotted-control-*`, defaulting from the field around it so a `size="sm"` field and its control cannot disagree.                                                                                                |
| A frame variant                                                     | both   | Fluent (`appearance`), Shoelace (`filled`), Radix (`variant`), Mantine, Chakra, Carbon (fluid) | adopt              | `variant="outline\|subtle\|plain"`. `plain` is the one a dense table needs: no border until the pointer or the caret is in it.                                                                                                                  |
| Adornment inside the frame, at the start and at the end             | TF     | Fluent, Primer, Polaris, Shoelace, Mantine, Chakra, Radix, Angular Material       | adopt                            | `prefix` and `suffix` parts inside the root, so the border, the padding and the click target belong to one box. Composition, not two props: a consumer puts an `icon`, a `kbd`, a unit or a `button` there.                                     |
| A clear button                                                      | TF     | Shoelace, Polaris, Mantine, Chakra                                                | adopt                            | `clearable`, drawn only when there is something to clear, emitting the value change with reason `clear` and returning focus to the input.                                                                                                       |
| A password reveal toggle                                            | TF     | Carbon, Shoelace, Polaris (via suffix), Ant                                       | adopt                            | `revealable`, valid only with `type="password"`, a real `button` with `aria-pressed` and a label an application translates.                                                                                                                     |
| A character counter bound to the value                              | both   | Carbon, Polaris, Angular Material, Ant                                            | adopt                            | The control counts; `field` places the count in its label row. The field's counter part already exists and the control feeds it, which is what `field`'s own inventory recorded as this wave's work.                                             |
| `maxLength` that stops the value                                    | both   | all thirteen (native)                                                            | adopt                            | Native attribute, passed through untouched.                                                                                                                                                                                                    |
| Type variants — text, email, url, tel, search, password             | TF     | React Aria, Fluent, Carbon, Shoelace, Polaris                                     | adopt                            | Native `type`, passed through. Nothing is re-declared: `inputMode`, `enterKeyHint`, `autocomplete`, `pattern`, `spellcheck` and `autocapitalize` reach the element because the props type is the element's.                                     |
| `disabled`, `readOnly`, `invalid`, `required` taken from the field  | both   | Base UI, Ark, Fluent, Chakra, Angular Material                                    | adopt                            | The mechanism `docs/superpowers/specs/2026-08-31-field-aware-controls-design.md` fixed: unset means ask the field, set means this regardless.                                                                                                    |
| The control mirrors those states onto itself for styling            | both   | Base UI (`data-*`), Ark, Chakra                                                   | adopt                            | `data-disabled`, `data-invalid`, `data-readonly` on the root; `data-required` is not mirrored, because the label draws the marker and an attribute that paints nothing is an attribute nothing reads.                                            |
| Native form participation                                           | both   | all thirteen                                                                     | adopt                            | `name`, `form`, `autocomplete` and submission are the element's. Angular adds `ControlValueAccessor`, which is where the ecosystems genuinely differ.                                                                                            |
| `focus()` and `select()` as imperative actions                      | both   | Shoelace, React Spectrum, Angular Material                                        | adopt                            | The native element itself: `ref` in React, `inputElement` on the `exportAs` instance in Angular. No wrapper method is invented for something the element already has.                                                                            |
| Rows as the control's starting height                               | TA     | all that ship a textarea (native `rows`)                                          | adopt                            | `rows`, default 3 rather than the platform's 2, because a two-row box reads as a mistyped input.                                                                                                                                                |
| Growing with the content                                            | TA     | Mantine (`autosize`), Angular CDK (`cdkTextareaAutosize`), Polaris (`autoSize`), Chakra (`autoresize`), Shoelace (`resize="auto"`) | adopt          | `autoSize`, implemented with CSS `field-sizing: content` — Baseline since June 2026 — with `rows` as the floor and `maxRows` as the ceiling. Nothing is measured on the main thread.                                                            |
| A ceiling on that growth                                            | TA     | Mantine (`maxRows`), Angular CDK (`cdkAutosizeMaxRows`), Polaris (`maxHeight`)    | adopt                            | `maxRows`, after which the control scrolls rather than pushing the page.                                                                                                                                                                        |
| Control over the manual resize handle                               | TA     | Fluent, Radix, Mantine, Polaris (native `resize`)                                 | adopt                            | `resize="block\|none\|both"`, defaulting to `block`. Horizontal resize breaks the field's own grid, so it is available and not the default. The handle is withdrawn while `autoSize` is on, because a control that sizes itself and a handle that fixes its size disagree on the next keystroke. |
| An indicator inside the control while something loads               | TF     | Primer (`loading`, `loaderPosition`), Polaris (`loading`)                         | defer to `progress-indicator` (wave 2) | The family is not built. Until it is, the `suffix` part holds whatever the application already spins, which is the composition that replaces the prop: `<TextField suffix={<Spinner />} />`.                                                    |
| Monospace value                                                     | both   | Primer (`monospace`), Polaris (`monospaced`)                                      | adopt                            | `mono`, reading `--slotted-font-family-mono`. A back-office form full of identifiers, hashes and keys is exactly the audience `PROJECT-PRD.md` names.                                                                                            |
| Application-wide defaults                                           | both   | Angular Material (`MAT_FORM_FIELD_DEFAULT_OPTIONS`), Mantine (theme)              | adopt                            | A provider in React and an injection token with `provideTextFieldDefaults()` in Angular, carrying `size`, `variant` and `mono`. Both bindings, where only one ecosystem ships it.                                                               |
| Substituting the rendered element of a part                         | both   | Base UI (`render`), Radix (`asChild`), Primer                                     | adopt                            | `render` in React; in Angular the parts are directives on the consumer's own element, which is the same reach.                                                                                                                                   |
| Text alignment inside the control                                   | TF     | Polaris (`align`)                                                                 | decline                          | One implementation of thirteen, and the one case that needs it — a right-aligned amount — belongs to `number-field` (wave 3, item 6), which knows the value is a number.                                                                        |
| Selecting the whole value when the control is focused               | TF     | Polaris (`selectTextOnFocus`)                                                     | decline                          | One of thirteen. `ref.current.select()` in an `onFocus` handler is the two lines that compose it, and it is the consumer's decision because it destroys click-to-place-caret.                                                                    |
| Connected controls on either side — a select, a button              | TF     | Polaris (`connectedLeft/Right`), Chakra (`startAddon`), Angular Material          | defer to `button-group` (wave 1, built) | An addon sits *outside* the frame and joins two bordered boxes into one. That is a group's rule about shared borders and corner radii, not a control's, and `button-group` already owns it.                                          |
| A frame that paints a warning distinct from an error                | both   | Carbon, Fluent (`validationState`)                                                | decline                          | The frame has one alarming state, and `invalid` is it: two levels of alarm in a border cannot be told apart without the message beside it. `inline-message` carries all five tones, so a warning is `tone="warning"` on `FieldError`.            |
| A floating label inside the frame                                   | both   | Angular Material (`floatLabel`), Carbon (fluid)                                   | decline                          | `field` owns the label and already places it above or beside the control. A floating label removes the description's place and makes the control's own frame responsible for a name it does not hold.                                             |
| Validation run by the control                                       | both   | Base UI (`match`), React Spectrum (`validationBehavior`)                          | defer to `form` (wave 3, item 8) | The control is told it is invalid. Deciding when it became invalid is submission orchestration, which `docs/build-order.md` assigns to `form`.                                                                                                 |
| Masking and formatting as you type                                  | TF     | Angular Material (third party), Polaris (none), Ant (none)                        | decline                          | `docs/component-features.md` §6 states it: a mask is an adapter, not a magic string. A formatter that owns the caret owns the value, and this family owns neither.                                                                                |

## 3. Differentiators

| Capability                                                                                | Why this library can hold it                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Auto-grow with no JavaScript                                                              | `field-sizing: content` reached Baseline in June 2026. Angular CDK caches a line height, writes the height on every `DoCheck` and re-measures on resize; Mantine ships a third-party component for it. The control here grows in the compositor, and the same rule works in the harness, in React and in Angular. |
| An adornment that keeps its own target size                                               | A `suffix` holding a button is held to `--slotted-target-min` by the family, not by the page, and the input's padding is derived from the adornment's own inline size, so a two-character unit and an icon both leave the caret where it belongs.                        |
| `plain` for a cell that is only a control while it is being used                          | A dense table is the audience `PROJECT-PRD.md` names first. `variant="plain"` paints no border at rest, one on hover and the focus ring on focus, and it keeps the exact same box, so a row does not reflow when the pointer crosses it.                                |
| The count is the control's and the place is the field's                                   | Carbon and Polaris count inside the control's own box; Angular Material counts in the subscript, where the count and the error fight for a row. Here the control publishes the count and `field` draws it in the spare column of the label row, which no surveyed implementation does. |
| The clear button and the reveal button are the same kind of thing                         | Both are real buttons inside the frame, both sit in `suffix`, both keep the caret, and both are held to the same target rule. Shoelace ships two unrelated attributes; Carbon ships the reveal and no clear.                                                            |
| Three schemes, three densities, logical properties                                        | The frame, the adornments, the placeholder and the clear button all read control scales the theme restates per density, so a dense form shrinks whole. In `dir="rtl"` the prefix is the visual end without a second stylesheet.                                          |
| Two bindings that reach their own ecosystem                                               | Angular gets `ControlValueAccessor` and an injection token; React gets a context provider and `render`. Nothing is levelled down to whichever ecosystem lacks the integration point.                                                                                    |

## 4. Gaps

| What a real product hits                                                              | What the family does                                                                                                                                                                                                                            |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The browser autofills the control and paints its own background over the theme        | `:autofill` is styled by the family in all three schemes, so an autofilled control still reads as this library's control rather than as Chrome's.                                                                                                  |
| A password manager or an extension injects a button on top of the suffix              | The suffix is inside the frame's padding and the input's own padding is reserved for it, so an injected control overlaps the frame's edge rather than the caret. Recorded as a limit rather than solved: nothing can stop an extension from drawing. |
| An unbroken 400-character token pasted into a textarea                                | `overflow-wrap: anywhere` in the textarea, so the value stays visible and nothing is removed from the DOM. The single-line control scrolls, which is the platform's answer and the right one.                                                        |
| Composing CJK or Vietnamese text                                                      | No event is intercepted and no value is rewritten during composition. The control reports what the element reports, which is the only behaviour that does not corrupt an IME.                                                                       |
| A textarea that grows past the viewport while the caret stays visible                 | `maxRows` is the ceiling and the control scrolls after it. Without a ceiling `field-sizing` would grow forever, which is the defect every auto-grow implementation ships first.                                                                     |
| The control is inside a `<fieldset disabled>` that never told it so                   | The stylesheet matches `:disabled` beside `[data-disabled]`, which is the defect the deleted `input` family recorded and fixed.                                                                                                                     |
| A placeholder longer than the control                                                 | Ellipsised rather than clipped mid-glyph, and never used as the name: `field` owns the label.                                                                                                                                                      |
| A clear button on a control the user cannot change                                    | It is withdrawn when the control is disabled or read-only, because a button that clears a read-only value is a button that lies.                                                                                                                    |
| Zoom to 200%, and a control in a 240-pixel drawer                                     | The frame is `min-inline-size: 0` and the adornments do not shrink below their target, so the input surrenders width first and the buttons stay hittable.                                                                                            |
| Escape pressed inside a control that lives in a dialog                                | Nothing is bound to Escape. Clearing on Escape — which some user agents do for `type="search"` — would swallow the key a dialog needs, and a control that traps Escape is a control a keyboard user cannot leave.                                     |

## 5. Delta against what shipped

`input` and `textarea` shipped on schema 4 and are deleted in this branch.

| What shipped                                            | What the field ships                                        | What these families ship                                                              |
| ------------------------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `.slotted-input` / `.slotted-textarea` class selectors  | —                                                            | `data-ui="text-field"` / `data-ui="textarea"` and `data-part`, no class in either sheet. |
| One part, `root`, and the element itself as the frame   | eight of thirteen wrap the input to hold adornments          | `root`, `input`, `prefix`, `suffix`, `clear`, `reveal`.                                  |
| Five capabilities, none of them mutable                 | every implementation holds the value                         | The value, with a controlled and an uncontrolled pair and a request carrying a reason.   |
| One axis, `size`                                        | six ship a frame variant                                     | `size`, `variant`, `mono`, and for the textarea `resize` and `autoSize`.                 |
| No clear, no reveal, no adornment                       | four, four and eight of thirteen respectively                | All three.                                                                               |
| No counter                                              | four ship one                                                | The control counts and `field` places it.                                                |
| No application-wide defaults                            | one ships them, for one framework                            | Provider and injection token, in both.                                                   |
| Hand-written block sizes — `1.75rem`, `2.25rem`         | —                                                            | `--slotted-control-height-*`, which is what makes the control answer density.            |
| `field-sizing` already used for auto-grow               | four ship auto-grow, three of them with JavaScript           | Kept, with the floor and the ceiling it was missing.                                     |
