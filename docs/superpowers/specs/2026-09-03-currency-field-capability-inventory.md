# Currency Field Capability Inventory

Produced before any design or code, from the field rather than from
`number-field`. The design beside this document —
`2026-09-03-currency-field-design.md` — says what the family is; this says what
it holds and what it refuses.

`number-field` already formats an amount through `Intl.NumberFormat`, so every
row below is weighed twice: once against the surveyed field, and once against
the family this library already ships. A row that `number-field` answers
completely is `defer to number-field`.

The field splits in two, and the split is the reason this family exists. The
design systems and the headless libraries treat currency as **a formatting
option on a number input**. The currency-only libraries — ngx-currency,
react-currency-input-field, react-currency-input, imask — treat it as **its own
control with its own typing model**, and all four of them are single-framework.
No surveyed implementation ships the second answer in two framework bindings.

## 2. Table stakes

| Capability                                                            | Who ships it                                                          | Verdict                | Reason                                                                                                                                                                             |
| --------------------------------------------------------------------- | --------------------------------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Currency formatting from an ISO 4217 code                             | React Aria, Base UI, Zag, PrimeNG, react-currency-input-field         | adopt                  | `currency` is a required prop, not a nested `format` object. A currency field with no currency is a number field.                                                                   |
| `currencyDisplay` — symbol, narrow symbol, code, name                 | PrimeNG, Intl, React Aria, Base UI, Zag                               | adopt                  | Own axis. `narrowSymbol` is the one an application usually wants (`$1` rather than `US$1`) and is invisible inside a nested options object.                                          |
| Fraction digits from the currency's minor units                       | Intl (ISO 4217 default), PrimeNG, react-currency-input-field, ngx-currency | adopt              | Resolved from `Intl`, never assumed to be two. JPY is nought, KWD is three, and `fractionDigits` overrides both.                                                                     |
| Grouping separators while typing                                      | All eleven                                                            | adopt                  | Written at commit, and on every keystroke under `entry="cents"` because the text is generated rather than typed.                                                                    |
| Locale-aware parsing of a pasted formatted amount                     | React Aria, Zag, Base UI, react-currency-input-field                  | defer to `@slotted/core/number` | `createNumberFormat` already builds its parser from `formatToParts`. This family extends it rather than writing a second one.                                                |
| `min` / `max` with a clamp policy                                     | Mantine (`clampBehavior`), Zag (`clampValueOnBlur`), Base UI (`allowOutOfRange`), React Aria (`commitBehavior`) | adopt | The `clamp` axis `number-field` already declares: `blur`, `strict`, `none`.                                                                         |
| Negative amounts, refusable                                           | ngx-currency (`allowNegative`), react-currency-input-field (`allowNegativeValue`), react-number-format (`allowNegative`), react-currency-input | decline | `min={0}` already says it, and it says it in the vocabulary the range is written in. A boolean beside a range is a second answer to one question, and the two can disagree. |
| Stepper buttons and arrow-key stepping                                | PrimeNG (`showButtons`), Base UI, Zag, React Aria, Carbon             | adapt                  | The `stepper` axis is inherited, and its default changes to `none`: PrimeNG defaults `showButtons` to false, and an invoice total is typed rather than nudged. `step` defaults to one major unit. |
| Prefix and suffix beside the value                                    | PrimeNG, Mantine, Ant (`addonBefore`), ngx-currency                   | adapt                  | `start` and `end` adornments, plus `currencyDisplay="none"` — the one value `Intl` has no option for — so the value is bare while the symbol sits beside it. This family adds the decision the others leave to the reader: the symbol inside the value is parsed and copied, the adornment is not. |
| Empty is not nought                                                   | Base UI (`number \| null`), ngx-currency (`nullable`), React Aria      | adopt                  | `number \| null`. A required amount left blank and an amount of nought are different facts.                                                                                         |
| Raw number submitted to a form                                        | React Aria (`name`), Zag (hidden input + `form`), Base UI, Mantine    | adopt                  | A hidden input carries the number; the visible control holds `R$ 1.480,00`, which no server wants.                                                                                  |
| Controlled and uncontrolled value with a reasoned request             | Base UI (eight reasons), React Aria, Zag, Mantine                     | adopt                  | `value` / `defaultValue` / `onValueChange`, over `@slotted/core/state`.                                                                                                             |
| Wheel does not change the value by accident                           | React Aria (`isWheelDisabled`), Ant (`changeOnWheel`), Zag            | adopt                  | Off unless `wheel` is set, and then only with focus on the control.                                                                                                                 |
| Text alignment for amounts                                            | ngx-currency (`align`, default `right`), react-currency-input, imask   | adapt                  | An `align` axis with logical values, defaulting to `end`: a column of amounts is compared on its last digit, and the cents-first caret already lives there.                          |
| Read-only, disabled and invalid inherited from the field              | Base UI (`Field.Root`), PrimeNG, Carbon                               | defer to `field`       | `docs/superpowers/specs/2026-08-31-field-aware-controls-design.md`: unset means ask the field.                                                                                       |
| Application-wide defaults                                             | ngx-currency (`provideEnvironmentNgxCurrency`), PrimeNG (locale config) | adopt                 | A product has one currency and one locale in nine screens out of ten. `provideCurrencyFieldDefaults()` and `CurrencyFieldDefaultsProvider` carry `currency`, `locale`, `entry`, `align`, `currencyDisplay`, `size`, `variant`, `stepper`, `clamp`. |
| Reactive Forms integration                                            | PrimeNG, ngx-currency                                                 | adopt                  | `ControlValueAccessor` on the Angular control, as every control in this library does.                                                                                               |
| Accounting negatives — `(R$ 1.234,56)`                                | Intl (`currencySign: 'accounting'`), passed through by React Aria, Base UI, Zag | adopt         | Written by `Intl` and **read back** by this family's parser, which is the half the surveyed parsers do not do.                                                                       |

## 3. Differentiators

| Capability                                                                                                  | Why it is here                                                                                                                                                                                                                                                                     |
| ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Cents-first entry** (`entry="cents"`), beside natural entry (`entry="natural"`)                           | ngx-currency is the only surveyed implementation that names it: `Financial` mode, its own default, where "numbers start at the highest precision decimal, typing a number shifts numbers left, the decimal character is ignored, most cash registers work this way" — `12` is `0,12`, `1234` is `12,34`. Neither React Aria, Base UI, Zag, PrimeNG, Carbon, Mantine nor Ant offers it, and no implementation offers it in two frameworks. It is what the invocation asked for and it is the family's reason to exist. |
| The entry model lives in `@slotted/core/currency`, not in a binding                                          | ngx-currency, react-currency-input-field, react-currency-input and imask each wrote the shifting rule inside one framework. Two bindings that disagreed about what the fourth keystroke of `1234` means would be two different controls with one name.                                 |
| Minor units drive the shift                                                                                  | ngx-currency's `precision` defaults to 2 whatever the currency is, so a JPY field types `¥12,34`. This family reads the exponent out of `Intl.NumberFormat(locale, { style: 'currency', currency })`, so `¥` shifts by nothing and `KWD` shifts by three.                              |
| The request carries the amount in minor units                                                                | No surveyed implementation does. A payment API is charged in integer cents, and `Math.round(value * 100)` is where a float becomes a rounding defect. Under `entry="cents"` the integer is what was typed, so it is exact by construction rather than by rounding.                     |
| `autocomplete="transaction-amount"` and the `transaction-currency` token documented                          | Standard autofill field names no surveyed implementation mentions, and WCAG 2.2 SC 1.3.5 (Identify Input Purpose) is satisfied by naming the purpose of the field.                                                                                                                    |
| Three colour schemes, three densities, `dir="rtl"` and logical properties                                    | What this library owns and none of the eleven do. A currency field is the hardest case for the last one: the amount, the symbol and the caret each have a direction, and a value in an RTL document is a bidirectional run.                                                            |
| `role="spinbutton"` with `aria-valuetext` reading the formatted amount                                       | React Aria strips the role and announces through a live region; this family keeps the APG's role, so a reader hears "one thousand four hundred and eighty reais" rather than "1480". Inherited from `number-field` with its cost recorded there.                                        |
| The symbol inside the value and the symbol beside it, shown together                                         | Mantine's `prefix` and Ant's `formatter` blur the two; PrimeNG ships both and documents neither against the other. The reference page shows them side by side because choosing wrongly is the mistake.                                                                                |

### Considered, not taken

- **Abbreviated input** — `1k` becoming 1000, from react-currency-input-field
  (`disableAbbreviations`). One surveyed implementation ships it. It collides
  with a locale whose grouping separator is a letter-adjacent character, and a
  bank statement never writes it. Declined.
- **A scrub area** — Base UI and Ark. Declined by `number-field` for needing
  Pointer Lock, and an amount is not a value anyone drags.
- **A currency selector inside the frame** — no surveyed implementation ships
  one. `select` is wave 6; until then the `end` adornment takes the consumer's
  own control, and the reference page writes the three lines.
- **`formatter` / `parser` callbacks** — Ant. A format `Intl` cannot write is a
  string, which is `text-field`'s.

## 4. Gaps

| What a real product hits                                                                                        | What no surveyed implementation does about it                                                                                                                                                              | What this family does                                                                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| An accounting amount is pasted back into the field it was copied from                                            | `Intl` writes `(R$ 1.234,56)` under `currencySign: 'accounting'` and every surveyed parser reads it as `1234,56` — a debit becomes a credit, silently.                                                        | The parser reads a fully parenthesised amount as negative, and the contract test states it.                                                                                    |
| The locale and the currency disagree — a Brazilian back office paying a US invoice                              | ngx-currency and react-currency-input configure separators by hand, so `pt-BR` plus `USD` is a manual combination that is usually wrong. PrimeNG and React Aria get it right and never say what governs what. | Separators and digits come from the locale; the symbol and the minor units come from the currency. The reference page shows `pt-BR` + `USD` as its own demonstration.           |
| A zero-decimal or three-decimal currency                                                                        | Every mask-based implementation defaults to a precision of two.                                                                                                                                              | Minor units are resolved per currency, and `entry="cents"` shifts by that number — nought for JPY, three for KWD.                                                               |
| The amount is longer than the field                                                                             | Not addressed anywhere in the eleven. A currency name (`currencyDisplay: 'name'`) can be forty characters.                                                                                                    | The value is one unbroken run, so the frame scrolls its own text rather than wrapping; the narrow-width capture and a `240px` scene prove it.                                   |
| A reader deletes the whole amount under cents-first entry                                                       | ngx-currency leaves `0,00` when `nullable` is false and the reader cannot tell an empty field from a zero one.                                                                                                | Backspace shifts right and empties to `null`, never to nought, and `Escape` is not bound — the deletion is a normal editing key.                                                |
| Money kept as a float                                                                                            | Every surveyed implementation holds a `number` and none of them says what that costs.                                                                                                                        | The cost is written in the design, the request carries the exact minor-unit integer, and the family points a ledger with more than fifteen significant digits at `text-field`.  |
| An amount typed on a phone                                                                                       | React Aria sniffs the user agent to pick `inputMode`, which is a hydration mismatch waiting to happen.                                                                                                        | `inputMode` is derived from the props, and under `entry="cents"` it is always `numeric`: the separator is never typed, so the keypad does not need one.                         |
