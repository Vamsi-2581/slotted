# List and List Item capability inventory

Produced before either family was designed or read, as
`.claude/skills/component/references/capability.md` requires. Both families are
new: `docs/build-order.md` lists `list list-item` in wave 4 and no scope
paragraph existed before this work. The paragraph written from this inventory
lands in the same commit.

Sources were read on 3 September 2026.

The set disagrees about what a list **is**. Carbon and the HTML specification
answer with a marked-up text list and nothing else. MUI and Angular Material
answer with a row of slots that is sometimes a link, sometimes a button and
sometimes a listbox option under the same name. Primer, Fluent and React Aria
answer with an interactive collection that owns roving focus, typeahead and a
selection model, and each of the three then hands the consumer a different role
to write on it — `menu`, `listbox` or `grid`.

`docs/component-features.md` section 10 decides for this library, and it decides
against the third answer: "Coleção interativa usa Listbox/Grid conforme
semântica, não `role=list` com teclado inventado." What follows is scoped by
that sentence: the family is a **static list whose rows may each be one
action**, and every capability that needs a collection keyboard is deferred by
name.

# List

## 2. Table stakes

| Capability                                      | Who ships it                                                        | Verdict                                             | Reason                                                                                                                                                                                                                          |
| ----------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ul` or `ol` as the root                        | HTML, Carbon, MUI (`component`), Angular Material                   | adopt                                               | `ordered` chooses the element. The reading order of a list of steps is a fact about the content, and only `ol` carries it.                                                                                                       |
| A painted marker: bullet, number, none          | HTML, Carbon, MUI (marker off by default)                           | adopt                                               | `marker` axis, independent of `ordered`. An `ol` with no painted number is a real case — a queue whose order matters and whose rows carry their own numbers.                                                                     |
| Rules between rows                              | MUI (`divider`), Primer (`showDividers`), Angular Material, Cloudscape | adopt                                               | `variant="ruled"`. One decision on the set rather than a boolean repeated on every row, which is what `accordion` already established for the same shape.                                                                        |
| A bounded surface around the whole list         | Cloudscape, Primer (`variant="inset"`), Polaris                     | adopt                                               | `variant="framed"`.                                                                                                                                                                                                             |
| Each row as its own surface                     | Polaris, Cloudscape                                                 | adopt                                               | `variant="separated"`. The fourth value completes the vocabulary `accordion` uses, so the two families cannot mean different things by the same word.                                                                            |
| Section headings                                | MUI (ListSubheader), Angular Material (`matSubheader`), Primer (Group + GroupHeading), React Aria (GridListSection + Header) | adopt                                               | A `list-section` member: an `li` holding a heading and a nested list, which is the grouping HTML already has. Four of the surveyed sources ship it and none of them nests the list, so each announces a heading loose in a set.  |
| A section heading that stays while it scrolls   | MUI (`ListSubheader` is sticky unless `disableSticky`)              | adopt                                               | `sticky` on the section. Composing it needs the family's own surface token and stack level; a consumer writing `position: sticky` alone gets a heading with rows showing through it.                                             |
| Row density                                     | MUI (`dense`), Angular Material (`appearance`), Cloudscape          | adapt                                               | The theme's `density` axis answers it for the whole application, and `size` stays for the three steps a single list chooses between. A family-level `dense` boolean would be a second density scale.                             |
| Gutters on or off                               | MUI (`disableGutters`), Primer (`variant: inset \| full`)           | adopt                                               | `inset` boolean. A list inside a `card` that already pads its body needs its rows flush with the card's edge, and a rule that stops short of the edge reads as a mistake.                                                        |
| An accessible name for the list                 | Angular Material (required on `mat-nav-list`), Primer, React Aria   | adopt                                               | `label` and `labelledBy`, forwarded to `aria-label` / `aria-labelledby`.                                                                                                                                                         |
| Empty state                                     | Cloudscape (`empty`), React Aria (`renderEmptyState`), Polaris      | adopt                                               | An `empty` part. It is an `li`, because a message placed outside the `ul` is outside the box the list paints and the reader hears "list, 0 items" and then nothing.                                                              |
| Loading                                         | Polaris (`loading`), React Aria (`LoadMoreItem`), Cloudscape        | adopt                                               | `loading` writes `aria-busy="true"` on the root, which is also what ARIA 1.2 §5.2.6 requires of a list whose required owned elements have not arrived yet.                                                                       |
| Nested lists                                    | HTML, Carbon, MUI (Collapse recipe), Angular Material               | adopt                                               | A list inside a row's `content`. It costs no API: `aria-level` is the platform's from the nesting, and the stylesheet indents by the marker column it already owns.                                                              |
| Virtualization / incremental loading            | MUI (react-window recipe), Fluent, React Aria (`LoadMoreItem`)      | defer to the collection engine, wave 6              | `docs/build-order.md` retires `virtual-list` as a family and makes windowing a capability of the collection engine. `listbox` is its first consumer.                                                                             |
| Selection with roving focus, typeahead, `Home`/`End` | Fluent (`selectionMode` + `navigationMode`), Angular Material (`mat-selection-list`), React Aria GridList, Primer (`selectionVariant` + an explicit `role`) | defer to `listbox` and `table`, wave 6              | `docs/component-features.md` §10 refuses `role="list"` with an invented keyboard, and ARIA 1.2 does not allow `aria-selected` on `listitem`. The row still paints a selection the page owns; what is deferred is the model that moves it. |
| Drag to reorder                                 | React Aria, Cloudscape                                              | defer to drag-and-drop `[Extended]`, guide §3       | The guide files it as invisible infrastructure shared by every collection, not as a list capability.                                                                                                                             |
| A horizontal or two-column arrangement          | React Aria (`layout="grid"`), Cloudscape                            | decline                                             | `grid` and `inline` own arrangement, and both already answer gap, alignment and wrapping. A list that flows sideways is `<Inline>` around the same rows: `<Inline gap="4">{rows}</Inline>`.                                       |

## 3. Differentiators

| What                                                                                                              | Why this library can                                                                                                                                                                                                                                    |
| ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **The family draws its own marker, and restores the semantics that costs.**                                       | CSS has no `display` that is both `list-item` and a grid, so any list whose rows carry a trailing control has already lost the native marker. The bullet becomes the library's own dot geometry and the number a counter, and `role="list"` is written for the stated reason. MUI never writes it and loses the semantics in Safari; Angular Material writes it and says nothing. |
| **`ordered` and `marker` are two questions.**                                                                     | Every surveyed implementation ties the number a reader hears to the number a reader sees. They are the same decision only by accident, and separating them is what lets a numbered queue paint its own badges without losing the reading order.           |
| **The set's variants and the section's are one vocabulary shared with `accordion`.**                              | `plain`, `ruled`, `framed`, `separated` already mean something in this library. A second family choosing its own four words is how a design system stops being one.                                                                                       |
| **Three colour schemes, three densities and `dir="rtl"` from one authored stylesheet, in both bindings.**          | No surveyed list ships a high-contrast scheme; the marker column, the inset and the sticky heading each have to mirror, and a single logical-property stylesheet is what makes that free.                                                                  |

## 4. Gaps

| What no surveyed implementation handles                                                                  | What this family does                                                                                                                                                                             |
| -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A sticky section heading over `separated` rows, where the rows have their own surface and their own edge. | The heading takes the list's own surface and the sticky stack level from `--slotted-z-index-sticky`, so a row scrolling under it is covered rather than showing through.                           |
| A list dropped into a box that already pads its own content — a `card` body, a `dialog`.                 | `inset` gives the rows their inline padding back **and** drops the frame, so the rule and the hover fill run edge to edge. MUI's `disableGutters` removes the padding and leaves the line inset, which draws a rule stopping short of the box it is in. |
| An empty list that is empty for two different reasons — nothing yet, or nothing matching.                | The `empty` part holds whatever the page puts in it, which is where `result-state` goes; the family supplies the box, the row height and the `aria-busy` interaction, not the words.               |

# List Item

## 2. Table stakes

| Capability                                    | Who ships it                                                                                          | Verdict                          | Reason                                                                                                                                                                                                                                              |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A leading visual                              | MUI (ListItemIcon, ListItemAvatar), Angular Material (`matListItemIcon`, `matListItemAvatar`), Primer (LeadingVisual), React Aria | adopt                            | One `start` part rather than two components. An icon and an avatar differ in size, and the size is the avatar's own; what the row owns is the column and its alignment.                                                                              |
| A title and one or more secondary lines       | MUI (ListItemText `primary`/`secondary`), Angular Material (`matListItemTitle` + `matListItemLine`), Primer (Description, inline or block) | adopt                            | `label` and `description`. `label` owns the truncation and the `unicode-bidi` isolation, which is the same reason `tag`, `tabs` and `collapsible` each give the words a box.                                                                         |
| Trailing metadata                             | MUI (`secondaryAction`), Angular Material (`matListItemMeta`), Primer (TrailingVisual)                | adopt                            | `end`, inside the actionable box, for a timestamp, a badge or a count that is part of what the row says.                                                                                                                                             |
| The whole row is one action                   | MUI (ListItemButton), Angular Material (`mat-action-list`), Primer (Item), Fluent (`onAction`)        | adopt                            | The `list-item-button` member: `li > button`.                                                                                                                                                                                                        |
| The whole row is one destination              | MUI (`component="a"`), Angular Material (`mat-nav-list`), Primer (LinkItem), React Aria (`href`)      | adopt                            | The `list-item-link` member: `li > a`.                                                                                                                                                                                                              |
| Independent action targets inside a row       | MUI (`secondaryAction`), Primer, React Aria GridList                                                  | adopt                            | The `actions` part, a **sibling** of the actionable box. Interactive content may not nest inside `a` or `button`, so this is the one arrangement that lets a row navigate and still carry its own delete control.                                     |
| `selected`                                    | MUI, Angular Material, Primer, Fluent                                                                 | adapt                            | A state the page states, painted from `data-selected`, exactly as `card` does. `aria-selected` is not valid on `listitem`, so the announcement belongs to the checkbox or the control the page puts in `start`.                                       |
| `current` / active                            | Angular Material (`activated`), Primer (`active`)                                                     | adopt                            | `current`, writing `aria-current`. It is inherited by `listitem` in ARIA 1.2 and is the one selection-shaped state a static list may announce itself.                                                                                                |
| `disabled`                                    | MUI, Primer, React Aria (`isDisabled`)                                                                | adapt                            | The attribute goes on the `content` element — `disabled` on the button, `aria-disabled` on the link — and never on the `li`: ARIA 1.2 deprecates `aria-disabled` on `listitem`. No surveyed implementation says so; MUI writes it on the row.        |
| `loading` on one row                          | Polaris, guide §10                                                                                    | adopt                            | `aria-busy` on the row, the action refused while it holds, and the width preserved, which is what `docs/component-features.md` §2.5 requires of every loading state.                                                                                 |
| A destructive row                             | Primer (`variant="danger"`)                                                                           | adapt                            | `tone`, with the library's five. Shipping one of a scale the theme already carries in full, and hiding four, would be the invention.                                                                                                                 |
| Alignment for a multi-line row                | MUI (`alignItems`), Angular Material (two- and three-line rows)                                       | adopt                            | `align`: `center` for one line, `start` for a row whose leading visual must sit with the title rather than with the block.                                                                                                                           |
| Text aligned past an absent leading visual    | MUI (ListItemText `inset`)                                                                            | adopt                            | `inset` on the row, so rows with and without an icon line their titles up in one column.                                                                                                                                                            |
| Row size                                      | Primer (`size: medium \| large`)                                                                      | adapt                            | Resolved from the list, then the provider, then `md`. A row that sized itself against its list would be a second answer to one question.                                                                                                             |
| Truncation of a title the row cannot grow for | Primer guidance, Angular Material single-line rows                                                    | adopt                            | `truncate`, and the content stays in the DOM — the briefing's standing decision.                                                                                                                                                                     |
| `onAction` separate from `onClick`            | Fluent, React Aria                                                                                    | decline                          | The member is a real `button` or `a`, so `onClick`, `onKeyDown` and the modified click a browser gives an anchor are the platform's already. A second event for the same transition is what `docs/state-and-events.md` refuses by name.              |
| `inactiveText`                                | Primer only                                                                                           | decline                          | One source, and `disabled` with a `description` says it: `<ListItem disabled><ListItemLabel>…</ListItemLabel><ListItemDescription>Unavailable while the index rebuilds</ListItemDescription></ListItem>`.                                             |
| `aria-posinset` / `aria-setsize` on each row  | ARIA 1.2, React Aria                                                                                  | adopt                            | `position` and `setSize`, forwarded only when the page states them. ARIA 1.2 says they are unnecessary while every row is in the DOM and necessary the moment only part of the set is, which is the case a paginated or filtered list is always in.  |

## 3. Differentiators

| What                                                                                             | Why this library can                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Three members instead of one `component` prop.**                                               | A static row, a row that is a button and a row that is a link are three different accessibility trees. MUI and Angular Material pick between them with a string, which means the wrong string produces a `div` a reader cannot reach and nothing says so.        |
| **`actions` is a sibling of `content`, and the contract says so.**                               | Every surveyed implementation lets a consumer nest a button inside the row's own button. Making the arrangement the only one the parts express is what keeps the row from producing invalid, unfocusable HTML.                                                    |
| **The disabled attribute never lands on the `li`.**                                              | ARIA 1.2 deprecated `aria-disabled` on `listitem`. The library owns both bindings and one stylesheet, so the state can be painted from `[data-disabled]` on the row while the attribute that means it sits on the element that can refuse an interaction.         |
| **The row answers its own inline size.**                                                         | `container-type: inline-size` on the row: below 22rem the trailing metadata moves under the title instead of squeezing it, which is the reflow `docs/component-features.md` §2.7 asks for and no surveyed list performs.                                          |

## 4. Gaps

| What no surveyed implementation handles                                                            | What this family does                                                                                                                                                                                       |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A title that is one unbroken token — a URL, a hash, a file name with no spaces.                    | `min-inline-size: 0` on the text column and `overflow-wrap: anywhere` on the label, so the token breaks instead of pushing the trailing metadata out of the row. MUI's `ListItemText` overflows here.        |
| A whole-row link with a trailing delete control.                                                   | The row's hit area is drawn by the `content` element itself and stops before `actions`, so the two targets never overlap and the delete control's focus ring is not clipped by the row's own overflow rule.  |
| A long translated title beside a timestamp that must not wrap.                                     | The title gives way and the metadata does not, then both stack below 22rem. Nothing surveyed states which one yields, so the answer varies with the string.                                                  |
| The 24 × 24 minimum on a trailing icon control inside a 30-pixel dense row.                        | The `actions` part spaces its targets by `--slotted-target-min` and expands each hit area past the visible control, which `docs/token-foundation.md` names as the family's job rather than the theme's.      |
