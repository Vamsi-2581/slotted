# Switch — capability inventory

Produced from the field rather than from the family, before any design or code.
`docs/rebuild-order.md` lists `switch` as a rebuild, and the family it names was
deleted with the rest of the schema-4 library: the tree holds no `switch`, and
`git show HEAD:specs/components/switch/contract.json` holds what shipped. The
delta against that contract is the last section.

Four of the ten build the control on a `button` and synthesise everything the
platform gives a checkbox; six build it on `input[type=checkbox]` and paint it.
That split is the family's first decision and it is taken in the design
document, not here.

## 2. Table stakes

Every capability two or more of the ten ship.

| Capability                                                    | Who ships it                                                             | Verdict                        | Reason                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Checked with a controlled and an uncontrolled pair            | all ten                                                                  | adopt                          | `checked` / `defaultChecked` / `onCheckedChange` in React, `model()`-shaped input plus `ControlValueAccessor` in Angular, both over `@slotted/core/state`.                                                                                                                          |
| A change request carrying why it was requested                | Base UI (`eventDetails`), Fluent (`ev` + `data`), Material (`change`)     | adopt                          | `pointer`, `keyboard` and `programmatic`, recovered from the click's `detail` and `isTrusted`. None of the ten lets a consumer refuse the move; this one does, because the request is cancellable before anything commits.                                                          |
| `disabled`                                                    | all ten                                                                  | adopt                          | Native `disabled` on the control: out of the tab order, out of submission. Unstated rather than `false`, so it defers to the field.                                                                                                                                                 |
| `readOnly`                                                    | Base UI, Ark, React Aria, Carbon                                         | adopt                          | The native `readonly` attribute does nothing on a checkbox, so the family implements it: `aria-readonly`, the activation refused, focus and submission kept. A read-only switch must not be mistakable for a disabled one.                                                          |
| `required`                                                    | Radix, Base UI, Ark, React Aria, Material, Mantine                       | adopt                          | `aria-required`, never the native attribute, which would engage browser constraint validation as a side effect of describing a field. Taken from the field when the field says so.                                                                                                  |
| `invalid`                                                     | Ark, Base UI (through `Field`), Mantine (`error`)                        | adopt                          | Unstated rather than `false`; `aria-invalid` on the control, `data-invalid` on the root, and the focus ring retargeted the way `text-field` established.                                                                                                                            |
| Native form participation — `name`, `value`, `form`, reset    | Radix, Base UI, Ark, React Aria, Material, Fluent, Mantine               | adopt                          | The real `input[type=checkbox]` is the control, so `name`, `value` (default `on`), `form` and `form.reset()` are the platform's and nothing is synthesised.                                                                                                                         |
| Size steps                                                    | Carbon (`sm`/`md`), Primer (`small`/`medium`), Fluent, Mantine           | adopt                          | `sm` / `md` / `lg`, from `--slotted-control-*`, resolved from the field first so a `size="sm"` field and its control cannot disagree about one row.                                                                                                                                 |
| A mark inside the thumb                                       | Material (`hideIcon`), Mantine (`thumbIcon`), Primer (line and circle)    | adopt                          | `indicator="mark"` draws `--slotted-icon-check` in the thumb when the switch is on and nothing when it is off, which is what `docs/component-features.md` asks for: the state readable beyond colour and beyond position. `indicator="none"` withdraws it.                            |
| A word for the state, beside the control                      | Primer (`On`/`Off` with `statusLabelPosition`), Carbon (`labelA`/`labelB`), Mantine (`onLabel`/`offLabel`, inside the track) | decline — the mark and the label carry it | The three that draw it have no description to draw. Here the mark carries the state without colour and without position, and the label and the description carry the meaning; a third text saying "On" beside a labelled control is the same fact three times. A product that wants the word writes it in the label. |
| A label attached to the control                               | Material, Ark, Mantine, React Aria, Carbon, Fluent, Base UI               | adopt                          | A `label` part pointing at the control through `for`, with `labelPlacement` and a `description` under it. The first draft declined this and gave the label to `field`; the reviewer rejected that, and `checkbox` — settled one item earlier in the same wave — had already answered it this way. A binary control names itself. |
| A group of switches with one legend                           | Mantine (`Switch.Group`), APG (`group` / `fieldset` + `legend`)          | defer to `field-group` (built) | `field-group` absorbed `fieldset` in wave 3 and already draws the legend and the group's own description.                                                                                                                                                                           |
| Substituting the rendered element of a part                   | Base UI (`render`), Radix (`asChild`), Ark (`asChild`)                   | adopt                          | `render` on the root in React; in Angular the root is a directive on the consumer's own element, which is the same reach. The control is fixed: substituting the element that holds the value, the identifier and the submission would leave the family with nothing to be.           |
| Reaching the native input                                     | Base UI (`inputRef`), React Aria (`inputRef`), Material (`toggle()`)     | adopt                          | `ref` reaches the input in React and `inputElement` on the `exportAs` instance in Angular. `click()` is the platform's own imperative toggle, and it is reported as `programmatic` rather than mistaken for a key press.                                                             |
| Application-wide defaults                                     | Material (`MAT_SLIDE_TOGGLE_DEFAULT_OPTIONS`), Mantine (theme)           | adopt                          | A context provider in React and an injection token with `provideSwitchDefaults()` in Angular, carrying `size`, `indicator`, `labelPlacement` and `loadingLabel`. Both bindings, where only one ecosystem ships it.                                                    |
| State mirrored into the DOM for styling                       | Base UI, Ark, Primer, Radix                                              | adopt                          | `data-checked`, `data-disabled`, `data-readonly`, `data-invalid`, `data-loading` on the root, from the vocabulary `specs/contract.schema.mjs` declares.                                                                                                                              |
| Colour of the checked track                                   | Material (`color`), Mantine (`color`)                                    | decline — retuning, not an axis | `docs/component-features.md` §2.4 refuses arbitrary colour in the contract. An application repaints it once with `--slotted-switch-checked-background`, which is what the token layer is for; a tone axis on a binary control would encode meaning in colour the label has to carry.  |
| Corner radius                                                 | Mantine (`radius`), Material (theme)                                     | decline — retuning, not an axis | `--slotted-switch-radius`, one declaration for the application. A pill is the shape that distinguishes a switch from a checkbox, so it is not an axis a single instance moves.                                                                                                       |
| Focusable while disabled                                      | Fluent (`disabledFocusable`), Material (`disabledInteractive`)           | decline — `readOnly` is it     | The need is a control a reader can reach and be told about. `readOnly` already answers it and answers it better: focusable, announced as read-only rather than as disabled, and still submitted. Two ways to refuse an interaction is one too many.                                    |
| Ripple                                                        | Material (`disableRipple`)                                              | decline — no ripple exists      | Material Design's own idiom, not this library's. Press feedback is the thumb and the track, and it is drawn in the `active` state.                                                                                                                                                   |
| A `Validator` making `required` mean "must be on"             | Material                                                                | decline — Reactive Forms owns it | `Validators.requiredTrue` is the one line that composes it, and it belongs to the form rather than to the control: a switch that validated itself would disagree with the form's own validators about who reports the error.                                                          |
| A store or hook exposing the machine                          | Ark (`useSwitch`, `RootProvider`)                                        | decline — the state is one bit  | The controlled pair plus the cancellable request already gives a consumer everything a store would: the value, the moment it moves, the reason, and the right to refuse.                                                                                                              |

## 3. Differentiators

| Capability                                                       | Where it comes from                                                                                                                                                                                                             |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A pending switch, with a delayed announcement                    | Only Primer ships `loading` at all, and it has no state model to go with it. A switch is the one control whose effect is immediate, which in a real product means a write that can be in flight. `loading` refuses a second toggle, keeps the geometry, sets `aria-busy`, and announces the pending label politely after two seconds so a fast save says nothing. |
| A cancellable request carrying its reason                        | Base UI reports a reason; nobody lets a consumer refuse the move. A confirmation before a destructive setting is then a handler, not a controlled-mode dance.                                                                        |
| Three colour schemes, including `high-contrast`, and forced colours | None of the ten ships a high-contrast scheme. The thumb keeps an edge and the mark keeps the state legible when the palette is replaced entirely.                                                                                    |
| Three densities                                                  | Nine of the ten ship two size steps and no density. Here the track, the thumb, the mark and the status word all read the control scales, so a dense table row shrinks the switch whole rather than in parts.                          |
| A thumb that travels on the inline axis                          | The travel is `inset-inline-start`, so a right-to-left document mirrors it with no second rule and no `[dir]` selector. Radix, Fluent and Carbon all write a physical translation and flip it in a direction-specific rule.           |
| Field-aware with no wrapper                                      | `<Switch />` inside a `<Field>` takes the identifier, the description, `aria-invalid`, `aria-required`, `disabled` and read-only without being asked. Base UI and Ark reach this only through their own field components.              |
| Two first-class bindings                                         | `ControlValueAccessor` and DI-provided defaults in Angular, a context provider and `render` in React, from one contract and one stylesheet.                                                                                          |

## 4. Gaps

| What a real product hits                                       | The answer this family ships                                                                                                                                                                                       |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The save fails and the switch must go back                     | Controlled mode plus the cancellable request: the consumer holds the bit, refuses the move until the write returns, and the reference page shows the optimistic version and the pessimistic one side by side.          |
| A second toggle while the first is in flight                   | `loading` refuses activation at the click, before the DOM moves, so no request is queued behind another and the control never shows a state the server does not have.                                                  |
| A switch inside a disabled `fieldset`                          | The stylesheet matches `:disabled` on the control beside `[data-disabled]` on the root. A control disabled by an ancestor is never told, and the deleted `input` family shipped that defect once already.              |
| A translated status word beside a dense switch                 | The status is text in the control's own type scale, never squeezed, and it is `aria-hidden` because the control already announces its state — a visible word plus an announced state is the same fact read twice.       |
| Forced colours replacing the palette                           | The thumb keeps its own edge and the mark carries the state, so the switch does not collapse into a coloured pill with nothing in it.                                                                                  |
| Reduced motion                                                 | The travel and the track's colour both transition through motion-scale tokens, which the theme collapses to one millisecond. Nothing loops, so nothing has to be stopped.                                              |
| Below 24 CSS pixels                                            | The pill is 20 pixels tall at `md`; the root holds `--slotted-target-min` and the control covers it, so the target is at least 24 pixels in both axes at every step and every density.                                 |

## 5. Delta against what shipped

`git show HEAD:specs/components/switch/contract.json` — schema 4, one member,
five capabilities, none of them mutable.

| What shipped                                        | What the field ships                                             | What this family ships                                                                                                    |
| --------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `button` with `role="switch"` and no form value     | six of ten build on `input[type=checkbox]`                       | `input[type=checkbox][role=switch]`: a contract break, recorded in the design document with the move a consumer makes.       |
| `parts: ['root', 'thumb']`                          | root, control, track, thumb, a label and a description           | `root`, `control`, `track`, `thumb`, `label`, `description` — `checkbox`'s anatomy, down to the metrics.                     |
| `checked` with no state model                       | every one of the ten ships the controlled pair                    | `stateModel.checked`, with `defaultChecked`, `onCheckedChange` and the reasons `pointer`, `keyboard`, `programmatic`.        |
| `readOnly: "unsupported"`                           | four of ten ship it                                              | `readOnly`, implemented rather than declared unsupported.                                                                    |
| no loading, no label, no indicator                  | Primer, Carbon, Mantine and Material each ship one of the three   | `loading`, `label` with `description` and `labelPlacement`, and `indicator`.                                                 |
| `keys: ['Space', 'Enter']` on a button              | APG: Space required, Enter optional                              | Space, from the platform. Enter is not bound: on a checkbox inside a form Enter submits, and stealing it would break the form. |
| no application defaults                             | Material and Mantine ship them                                    | A provider in React and `provideSwitchDefaults()` in Angular.                                                                |
