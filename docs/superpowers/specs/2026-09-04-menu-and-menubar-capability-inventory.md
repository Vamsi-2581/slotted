# Menu and Menubar capability inventory

Written before the design, before the contract, and before any code, as
`.claude/skills/component/references/capability.md` requires. Both families are
new: `specs/components/` holds neither, and `packages/styles/src/` holds neither.

The scope paragraph is `docs/build-order.md`, wave 5, item 5, and the family
paragraph is `docs/component-features.md` §8, _Menu e Menubar `[Core]`_:

> Ações, checkbox/radio items, grupos, separators, submenus e atalhos; items têm
> ID, label, disabled e handler. Roving focus, typeahead, setas e Escape seguem
> APG. Submenu possui intent/grace area; ação fecha por padrão. Menu não é
> navegação genérica nem Select; itens representam comandos.

`PROJECT-PRD.md` names menus once, in the list of surfaces an application shell
composes (line 916). It sets no capability this inventory has to weigh, so
everything below comes from the field and from this repository's own law.

## 2. Table stakes

### 2.1 The surface and its state

| Capability                                                   | Who ships it                                              | Verdict            | Reason                                                                                                                                                                             |
| ------------------------------------------------------------ | --------------------------------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Controlled and uncontrolled `open`, plus a change request    | Radix, Base UI, Ark, React Aria, CDK                      | adopt              | `docs/state-and-events.md` requires it of every mutable value. `createControllable` holds both modes.                                                                               |
| A reason on the request                                      | Base UI (`eventDetails.reason`)                           | adopt              | One of five, and repository law here. `pointer`, `keyboard`, `escape`, `outsidePress`, `select`, `dismiss`, `programmatic`.                                                         |

The trigger's own text is the name; an instance may state `aria-label` instead.                                        |
| Portal, with an opt-out                                      | Radix, Base UI, Ark                                       | adopt              | `packages/core/src/portal`, which mirrors `dir`, theme, scheme and density onto the layer.                                                                                          |
| `side`, `align`, `sideOffset`, `alignOffset`                 | Radix, Base UI, Ark                                       | adopt              | `positioner`'s options. Default `bottom` / `start`, which is where a menu hangs from its button; `popover` centres and a menu does not.                                             |
| Flip, shift, collision boundary and padding                  | Radix, Base UI, Ark                                       | adopt              | `positioner`'s `flip`, `shift`, `boundary`, `boundaryPadding`.                                                                                                                     |
| `strategy` — absolute or fixed                               | Base UI, Ark                                              | adopt              | A menu inside `overflow: hidden` needs `fixed`; one inside a `transform` needs `absolute`.                                                                                          |
| `hideWhenDetached`                                           | Radix, Base UI, Ark                                       | adopt              | A menu whose button has scrolled out of a pane has nothing left to command. | Outside press closes                                         | Radix, Base UI, Ark, CDK                                  | adopt              | `dismissable-layer`, with the trigger and the menubar registered as branches so pressing either is inside the layer.                                                                |

A consumer who needs the page frozen is describing a dialog. |

| `dir` — the whole family mirrors                             | Radix (`dir`), Base UI, Ark, CDK                          | adopt              | Arrow keys swap on the inline axis, the submenu opens to the inline end, and the chevron mirrors. ## 3. Differentiators

| What                                                        | Where it comes from                                                                                                                                                                                                       |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A shortcut that is resolved rather than typed               | `packages/core/src/keys` already turns `Mod+K` into `⌘K` on Apple platforms and `Ctrl+K` elsewhere, and `kbd` already draws a key. No surveyed implementation resolves the platform: all five print whatever string the consumer wrote, on every operating system. |
| `aria-keyshortcuts` on the item                             | None of the five surveyed pages documents the attribute. A shortcut printed in the item is invisible to a reader who does not see it, and the attribute is the platform's own answer.                                       |
| Three densities                                             | Item height, the icon column, the gap and the type size all read control geometry, so a dense menu holds more commands without becoming a different component. No surveyed implementation has a density axis at all.        |
| Three colour schemes and forced colours                     | `high-contrast` is an application's choice here and the operating system's mode is the theme's `forced-colors` block. Radix, Base UI, Ark and React Aria each leave both to the consumer's stylesheet.                      |
| Two first-class bindings                                    | Radix, Base UI, Ark and React Aria are React; the CDK is Angular and unstyled. A menubar that is the same component in both frameworks is what none of them offers.                                                          |
| A request that carries a reason, and can be cancelled       | Only Base UI reports a reason. Here a consumer can tell Escape from an outside press from a selection, and refuse the close before it commits — which is what a menu that guards unsaved work needs.                         |
| The menubar as a container over the unchanged menu family   | Base UI reached the same shape; Radix and the CDK did not. It is what makes a menubar's menu inherit every capability listed in §2.2 at no cost, including the ones added after it.                                          |

## 4. Gaps

| What no surveyed implementation handles well               | What this family does                                                                                                                                                                                                                            |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A long or translated label beside a shortcut               | Every surveyed example lays an item out with a flex row and a pushed-right shortcut, which lets a German label eat the shortcut's column. The item is a grid: an icon column that exists only when a menu has icons, a label column that wraps at its measure, and a shortcut column that never shrinks. |
| A menu taller than the space under its button              | Radix, Base UI and React Aria each publish the remaining height as a custom property; Base UI adds a `Viewport` part and none of the three bounds itself by default. The content is bounded by `--slotted-positioner-available-height` and scrolls, so a menu never runs off the bottom of the screen. |
| An empty menu                                              | Only React Aria has `renderEmptyState`. An `empty` part, so a menu whose items were all filtered away says so instead of drawing a two-pixel-tall box.                                                                                              |
| A menu waiting for its items                               | None of the five states a loading menu. A `loading` state on the content, which keeps the surface's size and announces itself, rather than an empty box that arrives populated a moment later.                                                     |
| A submenu at the edge of the screen                        | All four flip it to the opposite inline side, and the pointer's grace area then points the wrong way. The grace area is computed from where the submenu actually landed, which `positioner`'s resolved side reports.                                |
| A hundred items                                            | Bounded height and scrolling hold it; virtualization is deferred to wave 6 with the reason written in §2.5. The typeahead is what makes a hundred items usable by keyboard, and it is adopted rather than optional.                                |
| A destructive command                                      | Named in §2.2: `tone` on the item, painting the label, the icon and the highlight from theme tones that already meet contrast in all three schemes.                                                                                                |
| The pointer crossing a disabled item on the way to a submenu | The grace area is geometry over the pointer's path, so it does not care what the pointer passes over — including a disabled item, which is where a hover-only implementation closes the submenu under the reader's hand.                            |

## 5. What this costs

Two modules land in `packages/core` before the family, each in its own commit,
each with its own test, as `docs/build-briefing.md` requires of shared tooling:

- `packages/core/src/typeahead` — a printable-character sequence matched against
  the labels of a list, with the reset window and the same-character cycling the
  APG describes. Wave 6's collection review inherits it.
- `packages/core/src/pointer-intent` — whether the pointer is moving toward a
  rectangle, so a submenu stays open while the pointer crosses the items between
  the parent item and the submenu. `preview-card` in wave 8 is the second
  consumer.

Both are additions to shared ground, which `docs/build-briefing.md` says must be
justified at the gate before being written. They are named here so the gate has
the reason in front of it.
